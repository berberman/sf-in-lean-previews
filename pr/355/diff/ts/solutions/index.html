1512+--  ### Automation with `solve_by_elim`
1513+
1514+--  When experimenting with definitions of programming languages in Lean,
1515+--  we often want to see what a particular term steps to - i.e., we want to
1516+--  find proofs for goals of the form `t ⟶* t'`. Consider, for example,
1517+--  reducing an arithmetic expression using the small-step relation
1518+--  `AStep`.
1519+
1520+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by
1521+  apply Multi.step (y := .p (.c 3) (.c 7))
1522+  . apply Step.plusRight
1523+    . apply IsValue.const
1524+    . apply Step.plus
1525+  . apply Multi.step (y := .c 10)
1526+    . apply Step.plus
1527+    . apply Multi.refl
1528+
1529+--  Proofs that one term normalizes to another must repeatedly apply
1530+--  `Multi.step` until the term reaches a normal form, with some very
1531+--  simple intermediate steps along the way. Thankfully, we can automate
1532+--  this process with a new tactic: `solve_by_elim`. When supplied with a
1533+--  list of constructors, `solve_by_elim [c₁, c₂, c₃, ...]` will attempt to
1534+--  apply these constructors repeatedly to a goal. It will also
1535+--  automatically attempt to use simple tactics like `rfl`, `trivial`,
1536+--  `congr` and hypotheses from the context in order to solve simple goals.
1537+--  So, for example, the proof above also be written:
1538+
1539+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by
1540+  repeat apply Multi.step <;>
1541+    try solve_by_elim [Step.plusRight, Step.plusLeft, Step.plus, IsValue.const]
1542+
1543+--  This one script would suffice to prove most concrete reduction
1544+--  sequences for this simple language. To make it work for others, we
1545+--  would need to supply constructors for those other languages to
1546+--  `solve_by_elim`. The languages we will study in this book can grow to a
1547+--  large number of constructors for their `Step` relations, so we'd like a
1548+--  way to supply all of them to `solve_by_elim` more easily. Luckily, Lean
1549+--  supports this. We can register a constructor (or lemma) for use with
1550+--  `solve_by_elim` with an `attribute` command:
1551+
1552+--  THE FOLLOWING DETAILS CAN BE SKIPPED (Attributes)
1553+--  The command below tags all of these constructors with the `SimpleArith`
1554+--  attribute, which we can then use to automatically pull all of these
1555+--  constructors in when we use `solve_by_elim`. However, due to a
1556+--  limitation of Lean, this attribute needs to be pre-declared in a
1557+--  different file; we can't create it here and then immediately use it.
1558+--
1559+--  For this book, we've predeclared all the attributes we'll use in a file
1560+--  called `AttributeDecls.lean`, following the typical pattern from
1561+--  libraries like Mathlib.
1562+--  END DETAILS
1563+
1564+attribute [SimpleArith] Step.plusRight Step.plusLeft Step.plus IsValue.const
1565+
1566+--  This `using` option then tells `solve_by_elim` to try to use every
1567+--  constructor we've registered with the supplied attribute:
1568+
1569+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by
1570+  repeat apply Multi.step <;>
1571+    try solve_by_elim using SimpleArith
1572+
1573+--  We can package all this up into a dedicated tactic for solving
1574+--  reduction sequences, which we'll call `normalize`:
1575+
1576+syntax "normalize" " using " ident,+ : tactic
1577+
1578+macro_rules
1579+  | `(tactic| normalize using $xs,*) =>
1580+    `(tactic| repeat apply Multi.step <;> try solve_by_elim (maxDepth:=10) using $xs,*)
1581+
1582+--  And voilà:
1583+
1584+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by
1585+  normalize using SimpleArith
1586+

1348+--  It's worth noting that `apply_rules` relies on an important property of
1349+--  our typing rules - namely, that they are *syntax directed*. A syntax
1350+--  directed judgment is one where the syntax of a term completely
1351+--  determines which rule can be applied at any given time; only one rule
1352+--  can be applied to each term. This is important because `apply_rules`
1353+--  just applies the first rule in its set of constructors or lemmas that
1354+--  it can - it doesn't backtrack if that rule isn't correct. So, making
1355+--  sure that only one rule can apply to any given term is important to
1356+--  ensure that `apply_rules` always discovers a valid derivation, if one
1357+--  exists.
