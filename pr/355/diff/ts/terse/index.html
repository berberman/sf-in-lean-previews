991+--  We can automate such tedious proofs with
992+--  `solve_by_elim`:
993+
994+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by
995+  repeat apply Multi.step <;>
996+    try solve_by_elim [Step.plusRight, Step.plusLeft, Step.plus, IsValue.const]
997+
998+--  This one script would suffice to prove most concrete
999+--  reduction sequences for this simple language. To make it
1000+--  work for others, we would need to supply constructors
1001+--  for those other languages to `solve_by_elim`. The
1002+--  languages we will study in this book can grow to a large
1003+--  number of constructors for their `Step` relations, so
1004+--  we'd like a way to supply all of them to `solve_by_elim`
1005+--  more easily. Luckily, Lean supports this. We can
1006+--  register a constructor (or lemma) for use with
1007+--  `solve_by_elim` with an `attribute` command:
1008+
1009+--  THE FOLLOWING DETAILS CAN BE SKIPPED (Attributes)
1010+--  The command below tags all of these constructors with
1011+--  the `SimpleArith` attribute, which we can then use to
1012+--  automatically pull all of these constructors in when we
1013+--  use `solve_by_elim`. However, due to a limitation of
1014+--  Lean, this attribute needs to be pre-declared in a
1015+--  different file; we can't create it here and then
1016+--  immediately use it.
1017+--
1018+--  For this book, we've predeclared all the attributes
1019+--  we'll use in a file called `AttributeDecls.lean`,
1020+--  following the typical pattern from libraries like
1021+--  Mathlib.
1022+--  END DETAILS
1023+
1024+attribute [SimpleArith] Step.plusRight Step.plusLeft Step.plus IsValue.const
1025+
1026+--  This `using` option then tells `solve_by_elim` to try to
1027+--  use every constructor we've registered with the supplied
1028+--  attribute:
1029+
1030+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by
1031+  repeat apply Multi.step <;>
1032+    try solve_by_elim using SimpleArith
1033+
1034+--  We can package all this up into a dedicated tactic for
1035+--  solving reduction sequences, which we'll call
1036+--  `normalize`:
1037+
1038+syntax "normalize" " using " ident,+ : tactic
1039+
1040+macro_rules
1041+  | `(tactic| normalize using $xs,*) =>
1042+    `(tactic| repeat apply Multi.step <;> try solve_by_elim (maxDepth:=10) using $xs,*)
1043+
1044+--  And voilà:
1045+
1046+example : (.p (.c 3) (.p (.c 3) (.c 4))) ⟶* (.c 10) := by

1199+--  It's worth noting that `apply_rules` relies on an
1200+--  important property of our typing rules - namely, that
1201+--  they are *syntax directed*. A syntax directed judgment
1202+--  is one where the syntax of a term completely determines
1203+--  which rule can be applied at any given time; only one
1204+--  rule can be applied to each term. This is important
1205+--  because `apply_rules` just applies the first rule in its
1206+--  set of constructors or lemmas that it can - it doesn't
1207+--  backtrack if that rule isn't correct. So, making sure
1208+--  that only one rule can apply to any given term is
1209+--  important to ensure that `apply_rules` always discovers
1210+--  a valid derivation, if one exists.
