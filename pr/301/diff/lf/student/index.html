410+-- ## Using Code Actions to Generate Match Skeletons
411+
412+-- Lean's language server can suggest *code actions*, which are small editor
413+-- commands that modify the source code. In VS Code, a lightbulb icon appears
414+-- on the left when a code action is available at your cursor. You can click
415+-- the icon or open the code action menu with `Ctrl + .` on Windows/Linux or
416+-- `Command + .` on macOS. For more information, see the [Lean 4 VSCode
417+-- extension
418+-- manual](https://github.com/leanprover/vscode-lean4/blob/master/vscode-lean4/manual/manual.md#code-actions).
419+
420+-- Some code actions can generate the explicit branches needed for pattern
421+-- matching. This is especially useful when working with `match` expressions,
422+-- or with tactics such as `cases` and `induction`, which we saw in previous
423+-- chapters.
424+
425+-- Let's look at an example using `induction`. For example, suppose we start
426+-- with the following incomplete proof:
427+
428+sf_expect_failure
429+  example (n : Nat) : Nat.beq n n := by
430+    induction n
431+
432+-- Note to developers (Mike Hicks @mwhicks1, NOW):
433+--     When I follow the instructions below in the student `.lean` files in
434+--     `_out` I do not get a lightbulb to do this code action. Instead I get a
435+--     couple of stars which if I click suggests a "quick fix".
436+
437+-- Put your cursor on `induction n` and open the code action menu. You should
438+-- see "Generate an explicit pattern match for 'induction'." in the list. If
439+-- you choose this action, Lean adds an explicit branch for each constructor:
440+
441+example (n : Nat) : Nat.beq n n := by
442+  induction n with
443+  | zero => sorry
444+  | succ n _ => sorry
445+
446+-- This gives us basic structure of the proof without requiring us to write
447+-- each branch by hand. We can then focus on proving each case.
448+
449+-- One possible proof is:
450+
451+example (n : Nat) : Nat.beq n n := by
452+  induction n with
453+  | zero => rfl
454+  | succ n ih => rw [Nat.beq, ih]
455+
456+-- Note that Lean used `_` for the induction hypothesis in the generated
457+-- `succ` branch. At that point, Lean didn't know whether the unfinished proof
458+-- would need to refer to the hypothesis. Since we use it in `rw`, we replace
459+-- `_` with the name `ih`.
460+
461+-- In later chapters, we will see some tactics that can make such inaccessible
462+-- names available again.
463+
464+-- The same trick also works for `match` expressions. For example, suppose we
465+-- start with
466+
467+sf_expect_failure
468+  def isZero (n : Nat) : Bool :=
469+    match n
470+
471+-- Lean can generate the missing branches:
472+
473+sf_expect_failure
474+  def isZero (n : Nat) : Bool :=
475+    match n with
476+    | 0 => _
477+    | n + 1 => _
