363+--  ## More about `cases`
364+
365+--  We've seen many examples where the `cases` tactic is used to perform
366+--  case analysis of the value of some variable. The tactic offers more
367+--  general-purpose functionality, too.
368+
369+--  For example, it turns out that `cases` builds in this same reasoning
370+--  that the `injection` and `contradiction` tactics exploit about the
371+--  injectivity and disjointness of constructors. Here are a few examples.
372+
373+-- substitution
374+example (x : Nat) (h : x = 0) : Nat.succ x = 1 := by
375+  cases h
376+  rfl
377+
378+-- disjointness
379+example (h : (0 : Nat) = 1) : 2 = 3 := by
380+  cases h
381+
382+-- injectivity
383+example {m n : Nat} (h : Nat.succ m = Nat.succ n) : m = n := by
384+  cases h
385+  rfl

387+--  Sometimes we need to reason by cases on the result of some
388+--  *expression*. We can do so with `cases`, directly. Here is an example:
389+
390+def chooseIf {α : Type} (test : α → Bool) (x y : α) : α :=
391+  if test x then x else y
392+
393+theorem chooseIf_self {α : Type} (test : α → Bool) (x : α) :
394+    chooseIf test x x = x := by
395+  rw [chooseIf]
396+  cases test x <;> rfl
397+
398+--  After *unfolding* `chooseIf` in the above proof, we find that we are
399+--  stuck on `(if test x = true then x else x) = x`. But either `test x` is
400+--  `true` or it isn't, so we can use `cases (test x)` to let us reason
401+--  about the two cases.
402+--
403+--  In general, the `cases` tactic can perform case analysis on the results
404+--  of arbitrary computations. If `e` has an inductively defined type `T`,
405+--  then `cases e` generates one subgoal for each constructor of `T`,
406+--  specializing the goal to that case. It does not necessarily rewrite
407+--  occurrences of `e` in hypotheses; when that information is needed, we
408+--  can save an equation as described below.

507+--  ## The `apply` Tactic
508+
509+--  We often encounter situations where the goal to be proved is *exactly*
510+--  the same as some hypothesis in the context or some previously proved
511+--  lemma.
512+
513+--  The `apply` tactic is useful when the goal is instead the conclusion of
514+--  an implication. If the conclusion of the implication matches the
515+--  current goal, its premises become new subgoals to be proved.
516+
517+--  For example, suppose we have a hypothesis `h : p → q` and our goal is
518+--  `q`. We can use `apply h` to replace the goal `q` with the premise `p`:
519+
520+example (p q : Prop) (h : p → q) (hp : p) : q := by
521+  apply h
522+  exact hp
523+
524+--  Here is another example:
525+
526+example (n m o p : Nat) (hnm : n = m) (h : n = m → [n, o] = [m, p]) :
527+    [n, o] = [m, p] := by
528+  apply h
529+  exact hnm
530+
531+--  When we use `apply h`, Lean tries to match the conclusion of the type
532+--  of `h` with the current goal. Here `h : n = m → [n, o] = [m, p]` has
533+--  conclusion `[n, o] = [m, p]`, which matches the current goal. Lean then
534+--  replaces the goal with the premise that is still needed, `n = m`. Then
535+--  we close the goal with `exact hnm`.
536+--
537+--  More generally, the type of a theorem or hypothesis used with `apply`
538+--  may have universally quantified variables and premises. Lean tries to
539+--  match its conclusion with the current goal to determine appropriate
540+--  values for the quantified variables.
541+
542+example (n m : Nat) (h₁ : (n, n) = (m, m))
543+    (h₂ : ∀ (q r : Nat), (q, q) = (r, r) → [q] = [r]) :
544+    [n] = [m] := by
545+  apply h₂
546+  exact h₁
