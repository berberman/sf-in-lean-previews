385+-- This facility is very powerful, and is used extensively in Lean to define
386+-- mathematical structures that carry both operators and laws about how those
387+-- operators interact. As a simple example, let's use a typeclass to define a
388+-- *monoid*, a simple algebraic structure that includes four things:
389+
390+-- - an underlying set of data, represented by a type `α`,
391+
392+-- - an operator (which we'll write `⊗`, typed otimes) that combines two
393+--   elements of type `α` into one,
394+
395+-- - a particular element `id` of type `α`, which we call the "identity
396+--   element", and
397+
398+-- - some laws about the interaction of `⊗` and `id`, namely that:
399+
400+--   - `∀ x, id ⊗ x = x = x ⊗ id`, and
401+--   - `∀ x y z, x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z` (i.e., that `⊗` is associative)
402+
403+-- We can express these requirements in the form of a typeclass:
404+
405+-- first we define a notation typeclass for our operator ⊗
406+class OpSet (α : Type) where
407+  op : α → α → α
408+
409+infixr:70 " ⊗ " => OpSet.op
410+
411+class Monoid (α : Type) extends (OpSet α) where
412+  id : α
413+  left_id : ∀ (x : α), id ⊗ x = x
414+  right_id : ∀ (x : α), x ⊗ id = x
415+  assoc : ∀ (x y z : α), x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z
416+
417+-- The `extends` keyword indicates that the `Monoid` typeclass extends the
418+-- `OpSet` typeclass, which just defines a set with an operator and some
419+-- notation for it. The `Monoid` typeclass "inherits" the fields of `OpSet`,
420+-- similar to how a class would in an object-oriented language.
421+
422+-- As one might expect, the `+` operator over `Nat`s forms a monoid, where `0`
423+-- is the identity element. Note that we don't have to define `Nat`'s `OpSet`
424+-- instance separately, we can define a single instance that implements both
425+-- classes.
426+
427+instance : Monoid Nat where
428+  op := Nat.add
429+  id := 0
430+  left_id := by lia
431+  right_id := by lia
432+  assoc := by lia

459+-- In addition to defining instances of `Monoid`, we can also prove some
460+-- properties about monoids in general, just based on the laws defined on the
461+-- typeclass. One simple theorem about monoids is that the identity element of
462+-- a monoid is unique. That is, if we have two monoids over the same set with
463+-- the same operator, their identity elements must also be the same:
464+
465+theorem id_unique {α : Type} {m₁ m₂ : Monoid α} (h : m₁.op = m₂.op) : m₁.id = m₂.id := by
466+  obtain @⟨op₁, id₁, left_id₁, right_id₁, assoc₁⟩ := m₁
467+  obtain @⟨op₂, id₂, left_id₂, right_id₂, assoc₂⟩ := m₂
468+  have h' : id₁ = id₂ := by
469+    -- this introduces a use of m₁'s operator
470+    rw [← left_id₁ id₂]
471+    -- we use our hypothesis to rewrite m₁'s operator into m₂'s
472+    rw [h]
473+    -- then, we can use m₂'s right id
474+    rw [right_id₂]
475+  -- the goal `m₁.id = m₂.id` is equivalent with `id₁ = id₂` even though it displays `Monoid.id = Monoid.id`
476+  exact h'
477+
478+-- In the above proof, we can destructure the monoid instances `m₁` and `m₂`
479+-- with the `obtain` tactic we saw in the Logic chapter. When we do so
480+-- however, because these are class instances instead of normal structures, we
481+-- preface our tuple with the `@` symbol. When stepping through the above
482+-- proof, if the notation is confusing to you, remember that you can set
483+-- `set_option pp.all true` or `set_option pp.explicit true` to make Lean show
484+-- you more clearly what is going on. For example, the goal is displayed as
485+-- `Monoid.id = Monoid.id` since the instances `m₁` and `m₂` are implicit
486+-- arguments to `Monoid.id`. Setting `pp.explicit true` displays the goal as
487+-- `@Eq α (@Monoid.id α m₁) (@Monoid.id α m₂)`.
488+
489+-- A *group* is a special kind of monoid with an *inverse* operation `inv`,
490+-- which has the property that `∀ x, inv x ⊗ x = id = x ⊗ inv x`. We can
491+-- extend the definition of a `Monoid` to capture this new feature:
492+
493+class Group (α : Type) extends (Monoid α) where
494+  inv : α → α
495+  left_inv : ∀ (x : α), inv x ⊗ x = id
496+  right_inv: ∀ (x : α), x ⊗ inv x = id
