11+-- ## Behavioral Equivaleence
12+
13+-- In an earlier chapter, we investigated the correctness of a very simple
14+-- program transformation: the `optimize0plus` function. The programming
15+-- language we were considering was the first version of the language of
16+-- arithmetic expressions -- with no variables -- so in that setting it was
17+-- very easy to define what it means for a program transformation to be
18+-- correct: it should always yield a program that evaluates to the same number
19+-- as the original.
20+
21+-- To talk about the correctness of program transformations for the full Imp
22+-- language -- in particular, assignment -- we need to consider the role of
23+-- mutable state and develop a more sophisticated notion of correctness, which
24+-- we'll call *behavioral equivalence*.
25+
26+-- For example:
27+
28+-- - `X + 2` is behaviorally equivalent to `1 + X + 1`
29+-- - `X - X` is behaviorally equivalent to `0`
30+-- - `(X - 1) + 1` is *not* behaviorally equivalent to `X`
31+
32+-- ### Definitions
33+
34+-- For `aexp`s and `bexp`s with variables, the definition we want is clear:
35+-- Two `aexp`s or `bexp`s are "behaviorally equivalent" if they evaluate to
36+-- the same result in every state.
37+
38+def Aexp.Equiv (a₁ a₂ : Aexp) : Prop :=
39+  ∀ (st : State),
40+    a₁.eval st = a₂.eval st
41+
42+theorem Aexp.equiv_def {a₁ a₂ : Aexp} :
43+    a₁.Equiv a₂ ↔ ∀ (st : State), a₁.eval st = a₂.eval st := by rfl
44+
45+def Bexp.Equiv (b₁ b₂ : Bexp) : Prop :=
46+  ∀ (st : State),
47+    b₁.eval st = b₂.eval st
48+
49+theorem Bexp.equiv_def {b₁ b₂ : Bexp} :
50+    b₁.Equiv b₂ ↔ ∀ (st : State), b₁.eval st = b₂.eval st := by rfl
51+
52+-- -- ::::full -- Here are some simple examples of equivalences of arithmetic
53+-- -- and boolean expressions. -- ::::
54+
55+example : Aexp.Equiv
56+    (aexp { X - X })
57+    (aexp { 0 }) := by
58+  rw [Aexp.equiv_def]
59+  intro st
60+  simp
61+
62+example : Bexp.Equiv
63+    (bexp { X - X = 0 })
64+    (bexp { true }) := by
65+  rw [Bexp.equiv_def]
66+  intro st
67+  simp
68+
69+-- For commands, the situation is a little more subtle. We can't simply say
70+-- "two commands are behaviorally equivalent if they evaluate to the same
71+-- ending state whenever they are started in the same initial state," because
72+-- some commands, when run in some starting states, don't terminate in any
73+-- final state at all!
74+
75+-- What we need instead is this: two commands are behaviorally equivalent if,
76+-- for any given starting state, they either (1) both diverge or else (2) both
77+-- terminate in the same final state. A compact way to express this is "if the
78+-- first one terminates in a particular state then so does the second, and
79+-- vice versa."
80+
81+def Com.Equiv (c₁ c₂ : Com) : Prop :=
82+    ∀ {st st' : State},
83+      (st =[ c₁ ]=> st') ↔ (st =[ c₂ ]=> st')
84+
85+theorem Com.equiv_def {c₁ c₂ : Com} : c₁.Equiv c₂ ↔
86+    ∀ {st st' : State}, (st =[ c₁ ]=> st') ↔ (st =[ c₂ ]=> st') := by rfl

130+-- Of course, no programmer would write a conditional whose condition is
131+-- literally `true`. (At least, no human programmer -- compilers and macro
132+-- preprocessors do this sort of thing internally all the time!) But they
133+-- might write one whose condition is *equivalent* to true:
134+
135+-- *Theorem*: If `b` is equivalent to `true`, then `if (~b) {~c₁}
136+-- else {~c₂}`
137+-- is equivalent to `c₁`. *Proof*:
138+
139+-- - (`->`) We must show, for all `st` and `st'`, that if
140+--   `st =[ imp {if (~b) {~c₁} else {~c₂}} ]=> st'` then `st =[ c₁ ]=> st'`.
141+
142+--   Proceed by cases on the rules that could possibly have been used to show
143+--   `st =[ imp {if (~b) {~c₁} else {~c₂}} ]=> st'`, namely `Com.EvalR.ifTrue`
144+--   and `Com.EvalR.ifFalse`.
145+
146+--   - Suppose the final rule in the derivation of
147+--     `st =[ imp {if (~b) {~c₁} else {~c₂}} ]=> st'` was `Com.EvalR.ifTrue`. We
148+--     then have, by the premises of `Com.EvalR.ifTrue`, that `st =[ c₁ ]=> st'`.
149+--     This is exactly what we set out to prove.
150+
151+--   - On the other hand, suppose the final rule in the derivation of
152+--     `st =[ imp {if (~b) {~c₁} else {~c₂}} ]=> st'` was `Com.EvalR.ifFalse`. We
153+--     then know that `b.eval st = false` and `st =[ c₂ ]=> st'`.
154+
155+--     Recall that `b` is equivalent to `true`, i.e., forall `st`,
156+--     `b.eval st = (bexp {true}).eval st`. In particular, this means that
157+--     `b.eval st = true`, since `(bexp {true}).eval st = true`. But this is a
158+--     contradiction, since `Com.EvalR.ifFalse` requires that `b.eval st = false`.
159+--     Thus, the final rule could not have been `Com.EvalR.ifFalse`.
160+
161+-- - (`<-`) We must show, for all `st` and `st'`, that if `st =[ c₁ ]=> st'`
162+--   then `st =[ imp {if (~b) {~c₁} else {~c₂}} ]=> st'`.
163+
164+--   Since `b` is equivalent to `true`, we know that `b.eval st` =
165+--   `(bexp {true}).eval st = true` = `true`. Together with the assumption that
166+--   `st =[ c₁ ]=> st'`, we can apply `Com.EvalR.ifTrue` to derive
167+--   `st =[ imp {if (~b) {~c₁} else {~c₂}} ]=> st'`.
168+

170+

173+  rw [equiv_def]
174+  rw [Bexp.equiv_def] at hb

176+  constructor
177+  · intro h
178+    inversion h with
179+    | ifTrue hb' hc =>
180+      exact hc
181+    | ifFalse hb' hc =>
182+      rw [hb] at hb'
183+      simp at hb'

231+-- Write an informal proof of `while_false_equiv`.
232+
233+-- To prove the second fact, we need an auxiliary lemma stating that `while`
234+-- loops whose guards are equivalent to `true` never terminate.
235+
236+-- *Lemma*: If `b` is equivalent to `true`, then it cannot be the case that
237+-- `st =[ while (~b) {~c} ]=> st'`.
238+
239+-- *Proof*: Suppose that `st =[ while (~b) {~c} ]=> st'`. We show, by
240+-- induction on a derivation of `st =[ while (~b) {~c} ]=> st'`, that this
241+-- assumption leads to a contradiction. The only two cases to consider are
242+-- `Com.EvalR.whileFalse` and `Com.EvalR.whileTrue`; the others are
243+-- contradictory.
244+
245+-- - Suppose `st =[ while (~b) {~c} ]=> st'` is proved using rule
246+--   `Com.EvalR.whileFalse`. Then by assumption `b.eval st = false`. But this
247+--   contradicts the assumption that `b` is equivalent to `true`.
248+
249+-- - Suppose `st =[ while (~b) {~c} ]=> st'` is proved using rule
250+--   `Com.EvalR.whileTrue`. We must have:
251+
252+--   1. `b.eval st = true`, and
253+
254+--   2. there is some `st₀` such that `st =[ c ] => st₀` and
255+--      `st₀ =[ while (~b) {~c} ]=> st'`.
256+
257+--   3. Also, we are given an induction hypothesis saying that
258+--      `st₀ =[ while (~b) {~c} ]=> st'` leads to a contradiction,
259+
260+--   We obtain a contradiction by 2 and 3.
261+
262+theorem while_true_nonterm {b : Bexp} {c : Com} {st st' : State} (hb : b.Equiv (bexp {true})) :
263+    ¬ st =[ while (~b) {~c} ]=> st' := by
264+  all_goals
265+    intro contra
266+    generalize heq : (imp {while (~b) {~c}}) = com at contra
267+    induction contra with
268+    | @whileFalse b' s0 c0 hb' =>
269+      injection heq with hbeq hceq
270+      subst hbeq
271+      rw [Bexp.equiv_def] at hb
272+      simp [hb] at hb'
273+    | @whileTrue s0 s0' s0'' b' c0 hb' hc' hwhile ih1 ih2 =>
274+      exact ih2 heq
275+    | skip | asgn | seq | ifTrue | ifFalse =>
276+      contradiction -- heq says that different commands are equal

418+-- ### Behavioral Equivalence is a Congruence
419+
420+-- Less obviously, behavioral equivalence is also a *congruence*. That is, the
421+-- equivalence of two subprograms implies the equivalence of the larger
422+-- programs in which they are embedded:
423+
424+-- aequiv a a' ------------------------- cequiv (x := a) (x := a')
425+
426+-- cequiv c1 c1' cequiv c2 c2' -------------------------- cequiv (c1;c2)
427+-- (c1';c2')
428+

430+

432+-- inductive definition, but simply to write down some valid implications in a
433+-- readable format. We prove these implications below.)
434+

436+-- important in the following section (in the proof of

440+-- explicit proof about the parts that didn't change -- i.e., the "proof
441+-- burden" of a small change to a large program is proportional to the size of
