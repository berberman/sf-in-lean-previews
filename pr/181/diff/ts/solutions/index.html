39+-- ## Canonical Forms
40+
41+-- As we saw for the very simple language in the Types chapter, the first step
42+-- in establishing basic properties of reduction and types is to identify the
43+-- possible *canonical forms* (i.e., well-typed values) belonging to each
44+-- type. For `Bool`, these are again the boolean values `true` and `false`;
45+-- for arrow types, they are lambda-abstractions.
46+
47+-- Formally, we will need these lemmas only for terms that are not only well
48+-- typed but *closed* — i.e., well typed in the empty context.
49+
50+theorem canonical_forms_bool (t : Tm) (hT : <{ ∅ ⊢ ~t ⦂ Bool }>) (hv : t.IsValue) :
51+    t = <{ true }> ∨ t = <{ false }> := by
52+  cases hv with
53+  | abs x T t₁ => cases hT
54+  | tru => exact .inl rfl
55+  | fls => exact .inr rfl
56+
57+theorem canonical_forms_fun (t : Tm) (T₁ T₂ : Ty)
58+    (hT : <{ ∅ ⊢ ~t ⦂ ~T₁ → ~T₂ }>) (hv : t.IsValue) :
59+    ∃ x u, t = <{ λ ~x : ~T₁ . ~u }> := by
60+  cases hv with
61+  | abs x T t₁ => cases hT with | abs _ _ _ _ _ _ => exact ⟨x, t₁, rfl⟩
62+  | tru => cases hT
63+  | fls => cases hT

65+-- ## Progress
66+
67+-- The *progress* theorem tells us that closed, well-typed terms are not
68+-- stuck: either a well-typed term is a value, or it can take a reduction
69+-- step. The proof is a relatively straightforward extension of the progress
70+-- proof we saw in the Types chapter. We give the proof in English first, then
71+-- the formal version.
72+
73+theorem progress (t : Tm) (T : Ty) (hT : <{ ∅ ⊢ ~t ⦂ ~T }>) :
74+    t.IsValue ∨ ∃ t', t ⟶ t' := by
75+  generalize hΓ : (∅ : Context) = Γ at hT
76+  induction hT with
77+  | var Γ x T₁ h =>
78+    subst hΓ
79+    -- Contradictory: variables cannot be typed in an empty context.
80+    rw [PartialMap.apply_empty] at h
81+    cases h
82+  | abs => exact .inl (.abs ..)
83+  | tru => exact .inl .tru
84+  | fls => exact .inl .fls
85+  | app Γ T₁ T₂ t₁ t₂ h₁ h₂ ih₁ ih₂ =>
86+    -- `t = t₁ t₂`.  Proceed by cases on whether `t₁` is a value or steps.
87+    right
88+    cases ih₁ hΓ with
89+    | inl hv₁ =>
90+      cases ih₂ hΓ with
91+      | inl hv₂ =>
92+        obtain ⟨x, u, rfl⟩ := canonical_forms_fun t₁ _ _ (hΓ ▸ h₁) hv₁
93+        exact ⟨<{ [~x := ~t₂] ~u }>, .appAbs x T₂ u t₂ hv₂⟩
94+      | inr hs₂ => obtain ⟨t₂', h⟩ := hs₂; exact ⟨<{ ~t₁ ~t₂' }>, .app2 t₁ t₂ t₂' hv₁ h⟩
95+    | inr hs₁ => obtain ⟨t₁', h⟩ := hs₁; exact ⟨<{ ~t₁' ~t₂ }>, .app1 t₁ t₁' t₂ h⟩
96+  | ite Γ t₁ t₂ t₃ T₁ h₁ h₂ h₃ ih₁ ih₂ ih₃ =>
97+    right
98+    cases ih₁ hΓ with
99+    | inl hv₁ =>
100+      cases canonical_forms_bool t₁ (hΓ ▸ h₁) hv₁ with
101+      | inl he => subst he; exact ⟨t₂, .ifTrue t₂ t₃⟩
102+      | inr he => subst he; exact ⟨t₃, .ifFalse t₂ t₃⟩
103+    | inr hs₁ =>
104+      obtain ⟨t₁', h⟩ := hs₁
105+      exact ⟨<{ if ~t₁' then ~t₂ else ~t₃ }>, .ifStep t₁ t₁' t₂ t₃ h⟩
106+
107+-- *Proof*: By induction on the derivation of `⊢ t ⦂ T`.
108+
109+-- - The last rule of the derivation cannot be `HasType.var`, since a variable
110+--   is never well typed in an empty context.
111+
112+-- - The `HasType.tru`, `HasType.fls`, and `HasType.abs` cases are trivial,
113+--   since in each of these cases we can see by inspecting the rule that `t` is
114+--   a value.
115+
116+-- - If the last rule of the derivation is `HasType.app`, then `t` has the form
117+--   `t₁ t₂` for some `t₁` and `t₂`, where `⊢ t₁ ⦂ T₂ → T` and `⊢ t₂ ⦂ T₂` for
118+--   some type `T₂`. The induction hypothesis for the first subderivation says
119+--   that either `t₁` is a value or else it can take a reduction step.
120+
121+--   - If `t₁` is a value, then consider `t₂`, which by the induction hypothesis
122+--     for the second subderivation must also either be a value or take a step.
123+
124+--     - Suppose `t₂` is a value. Since `t₁` is a value with an arrow type, it must
125+--       be a lambda abstraction; hence `t₁ t₂` can take a step by `Step.appAbs`.
126+
127+--     - Otherwise, `t₂` can take a step, and hence so can `t₁ t₂` by `Step.app2`.
128+
129+--   - If `t₁` can take a step, then so can `t₁ t₂` by `Step.app1`.
130+
131+-- - If the last rule of the derivation is `HasType.ite`, then
132+--   `t = if t₁ then t₂ else t₃`, where `t₁` has type `Bool`. The first IH says
133+--   that `t₁` either is a value or takes a step.
134+
135+--   - If `t₁` is a value, then since it has type `Bool` it must be either `true`
136+--     or `false`. If it is `true`, then `t` steps to `t₂`; otherwise it steps to
137+--     `t₃`.
138+
139+--   - Otherwise, `t₁` takes a step, and therefore so does `t` (by `Step.ifStep`).
140+

178+-- ## Preservation
179+
180+-- The other half of the type soundness property is the preservation of types
181+-- during reduction. For this part, we'll need to develop some technical
182+-- machinery for reasoning about variables and substitution. Working from top
183+-- to bottom (from the high-level property we are actually interested in to
184+-- the lowest-level technical lemmas that are needed by various cases of the
185+-- more interesting proofs), the story goes like this:
186+
187+-- - The *preservation theorem* is proved by induction on a typing derivation
188+--   and case analysis on the step relation, pretty much as we did in the Types
189+--   chapter. The one case that is significantly different is the one for the
190+--   `Step.appAbs` rule, whose definition uses the substitution operation. To
191+--   see that this step preserves typing, we need to know that the substitution
192+--   itself does. So we prove a...
193+
194+-- - *substitution lemma*, stating that substituting a (closed, well-typed) term
195+--   `s` for a variable `x` in a term `t` preserves the type of `t`. The proof
196+--   goes by induction on the form of `t` and requires looking at all the
197+--   different cases in the definition of substitition. This time, for the
198+--   variables case, we discover that we need to deduce from the fact that a
199+--   term `s` has type S in the empty context the fact that `s` has type S in
200+--   every context. For this we prove a...
201+
202+-- - *weakening* lemma, showing that typing is preserved under "extensions" to
203+--   the context `Γ`.
204+
205+-- To make Lean happy, though, we need to formalize the story in the opposite
206+-- order, starting with weakening...
207+
208+-- ### The Weakening Lemma
209+
210+-- First, we show that typing is preserved under "extensions" to the context
211+-- `Γ`. (Recall map inclusion, `Γ ⊆ Γ'`, from the `Typeclasses` chapter.)
212+
213+theorem weakening (Γ Γ' : Context) (t : Tm) (T : Ty)
214+    (hi : Γ ⊆ Γ') (hT : <{ ~Γ ⊢ ~t ⦂ ~T }>) : <{ ~Γ' ⊢ ~t ⦂ ~T }> := by
215+  induction hT generalizing Γ' with
216+  | var _ x _ h => exact .var _ x _ (hi x _ h)
217+  | abs _ x _ _ _ _ ih => exact .abs _ x _ _ _ (ih _ (PartialMap.update_subset _ _ _ _ hi))
218+  | app _ _ _ _ _ _ _ ih₁ ih₂ => exact .app _ _ _ _ _ (ih₁ _ hi) (ih₂ _ hi)
219+  | tru => exact .tru _
220+  | fls => exact .fls _
221+  | ite _ _ _ _ _ _ _ _ ih₁ ih₂ ih₃ => exact .ite _ _ _ _ _ (ih₁ _ hi) (ih₂ _ hi) (ih₃ _ hi)
222+
223+-- The following simple corollary is what we actually need below.
224+
225+theorem weakening_empty (Γ : Context) (t : Tm) (T : Ty) (hT : <{ ∅ ⊢ ~t ⦂ ~T }>) :
226+    <{ ~Γ ⊢ ~t ⦂ ~T }> :=
227+  weakening _ _ _ _
228+    (fun x T h => by rw [PartialMap.apply_empty] at h; cases h) hT

230+-- ### The Substitution Lemma
231+
232+-- Now we come to the conceptual heart of the proof that reduction preserves
233+-- types — namely, the observation that *substitution* preserves types.
234+
235+-- Formally, the so-called *substitution lemma* says this: Suppose we have a
236+-- term `t` with a free variable `x`, and suppose we've assigned a type `T` to
237+-- `t` under the assumption that `x` has some type `U`. Also, suppose that we
238+-- have some other term `v` and that we've shown that `v` has type `U`. Then,
239+-- since `v` satisfies the assumption we made about `x` when typing `t`, we
240+-- can substitute `v` for each of the occurrences of `x` in `t` and obtain a
241+-- new term that still has type `T`.
242+
243+theorem substitution_preserves_typing (Γ : Context) (x : String) (U : Ty)
244+    (t v : Tm) (T : Ty)
245+    (hT : <{ ~x ↦ ~U ; ~Γ ⊢ ~t ⦂ ~T }>) (hv : <{ ∅ ⊢ ~v ⦂ ~U }>) :
246+    <{ ~Γ ⊢ [~x := ~v] ~t ⦂ ~T }> := by
247+  -- By induction on `t`; in each case we get at the derivation of `hT`.
248+  induction t generalizing Γ T with
249+  | var y =>
250+    cases hT with
251+    | var _ _ _ h =>
252+      by_cases hxy : x = y
253+      · subst hxy
254+        rw [PartialMap.update_eq] at h
255+        rw [subst_var_eq]
256+        have hUT : U = T := Option.some.inj h
257+        subst hUT
258+        exact weakening_empty _ _ _ hv
259+      · rw [PartialMap.update_neq _ _ _ hxy] at h
260+        rw [subst_var_ne _ _ _ hxy]
261+        exact .var _ y _ h
262+  | app t₁ t₂ ih₁ ih₂ =>
263+    cases hT with
264+    | app _ _ _ _ _ h₁ h₂ => rw [subst_app]; exact .app _ _ _ _ _ (ih₁ _ _ h₁) (ih₂ _ _ h₂)
265+  | abs y S t₁ ih =>
266+    cases hT with
267+    | abs _ _ _ _ _ h =>
268+      by_cases hxy : x = y
269+      · subst hxy
270+        rw [subst_abs_eq]
271+        rw [PartialMap.update_shadow] at h
272+        exact .abs _ _ _ _ _ h
273+      · rw [subst_abs_ne _ _ _ _ _ hxy]
274+        rw [PartialMap.update_permute _ _ _ _ _ (Ne.symm hxy)] at h
275+        exact .abs _ _ _ _ _ (ih _ _ h)
276+  | tru => cases hT with | tru => rw [subst_tru]; exact .tru _
277+  | fls => cases hT with | fls => rw [subst_fls]; exact .fls _
278+  | ite c t e ihc iht ihe =>
279+    cases hT with
280+    | ite _ _ _ _ _ h₁ h₂ h₃ =>
281+      rw [subst_ite]
282+      exact .ite _ _ _ _ _ (ihc _ _ h₁) (iht _ _ h₂) (ihe _ _ h₃)
283+
284+-- The substitution lemma can be viewed as a kind of "commutation property."
285+-- Intuitively, it says that substitution and typing can be done in either
286+-- order: we can either assign types to the terms `t` and `v` separately
287+-- (under suitable contexts) and then combine them using substitution, or we
288+-- can substitute first and then assign a type to ` `x:=v` t`; the result is
289+-- the same either way.
290+
291+-- *Proof*: We show, by induction on `t`, that for all `T` and `Γ`, if
292+-- `x ↦ U; Γ ⊢ t ⦂ T` and `⊢ v ⦂ U`, then `Γ ⊢ [x:=v]t ⦂ T`.
293+
294+-- - If `t` is a variable there are two cases to consider, depending on whether
295+--   `t` is `x` or some other variable.
296+
297+--   - If `t = x`, then from the fact that `x ↦ U; Γ ⊢ x ⦂ T` we conclude that
298+--     `U = T`. We must show that `[x:=v]x = v` has type `T` under `Γ`, given the
299+--     assumption that `v` has type `U = T` under the empty context. This follows
300+--     from the weakening lemma.
301+
302+--   - If `t` is some variable `y` that is not equal to `x`, then we need only
303+--     note that `y` has the same type under `x ↦ U; Γ` as under `Γ`.
304+
305+-- - If `t` is an abstraction `λy:S. t₀`, then `T = S→T₁` and the IH tells us,
306+--   for all `Γ'` and `T₀`, that if `x ↦ U; Γ' ⊢ t₀ ⦂ T₀`, then
307+--   `Γ' ⊢ [x:=v]t₀ ⦂ T₀`. Moreover, by inspecting the typing rules we see it
308+--   must be the case that `y ↦ S; x ↦ U; Γ ⊢ t₀ ⦂ T₁`.
309+
310+--   The substitution in the conclusion behaves differently depending on whether
311+--   `x` and `y` are the same variable.
312+
313+--   First, suppose `x = y`. Then, by the definition of substitution,
314+--   `[x:=v]t = t`, so we just need to show `Γ ⊢ t ⦂ T`. Using `HasType.abs`, we
315+--   need to show that `y ↦ S; Γ ⊢ t₀ ⦂ T₁`. But we know
316+--   `y ↦ S; x ↦ U; Γ ⊢ t₀ ⦂ T₁`, and the claim follows since `x = y`.
317+
318+--   Second, suppose `x <> y`. Again, using `HasType.abs`, we need to show that
319+--   `y ↦ S; Γ ⊢ [x:=v]t₀ ⦂ T₁`. Since `x <> y`, we have
320+--   `y ↦ S; x ↦ U; Γ = x ↦ U; y ↦ S; Γ`. So we have
321+--   `x ↦ U; y ↦ S; Γ ⊢ t₀ ⦂ T₁`. Then, the the IH applies (taking
322+--   `Γ' = y ↦ S; Γ`), giving us `y ↦ S; Γ ⊢ [x:=v]t₀ ⦂ T₁`, as required.
323+
324+-- - If `t` is an application `t₁ t₂`, the result follows straightforwardly from
325+--   the definition of substitution and the induction hypotheses.
326+
327+-- - The remaining cases are similar to the application case.
328+
329+-- One technical subtlety in the statement of the above lemma is that we
330+-- assume `v` has type `U` in the *empty* context — in other words, we assume
331+-- `v` is closed. (Since we are using a simple definition of substition that
332+-- is not capture-avoiding, it doesn't make sense to substitute non-closed
333+-- terms into other terms. Fortunately, closed terms are all we need!)
334+

339+
340+theorem substitution_preserves_typing_from_typing_ind (Γ : Context) (x : String) (U : Ty)
341+    (t v : Tm) (T : Ty)
342+    (hT : <{ ~x ↦ ~U ; ~Γ ⊢ ~t ⦂ ~T }>) (hv : <{ ∅ ⊢ ~v ⦂ ~U }>) :
343+    <{ ~Γ ⊢ [~x := ~v] ~t ⦂ ~T }> := by
344+  all_goals
345+    generalize hΓ : (x →ₚ U ; Γ) = Γ₀ at hT
346+    induction hT generalizing Γ with
347+    | var _ y T₁ h =>
348+      subst hΓ
349+      by_cases hxy : x = y
350+      · subst hxy
351+        rw [PartialMap.update_eq] at h
352+        rw [subst_var_eq]
353+        have hUT : U = T₁ := Option.some.inj h
354+        subst hUT
355+        exact weakening_empty _ _ _ hv
356+      · rw [PartialMap.update_neq _ _ _ hxy] at h
357+        rw [subst_var_ne _ _ _ hxy]
358+        exact .var _ y _ h
359+    | abs _ y _ _ _ hb ih =>
360+      subst hΓ
361+      by_cases hxy : x = y
362+      · subst hxy
363+        rw [subst_abs_eq]
364+        rw [PartialMap.update_shadow] at hb
365+        exact .abs _ _ _ _ _ hb
366+      · rw [subst_abs_ne _ _ _ _ _ hxy]
367+        exact .abs _ _ _ _ _ (ih _ (PartialMap.update_permute _ _ _ _ _ hxy))
368+    | app _ _ _ _ _ _ _ ih₁ ih₂ =>
369+      rw [subst_app]; exact .app _ _ _ _ _ (ih₁ _ hΓ) (ih₂ _ hΓ)
370+    | tru => rw [subst_tru]; exact .tru _
371+    | fls => rw [subst_fls]; exact .fls _
372+    | ite _ _ _ _ _ _ _ _ ih₁ ih₂ ih₃ =>
373+      rw [subst_ite]; exact .ite _ _ _ _ _ (ih₁ _ hΓ) (ih₂ _ hΓ) (ih₃ _ hΓ)

375+-- ### Main Theorem
376+
377+-- We now have the ingredients we need to prove preservation: if a closed,
378+-- well-typed term `t` has type `T` and takes a step to `t'`, then `t'` is
379+-- also a closed term with type `T`. In other words, the small-step reduction
380+-- relation preserves types.
381+
382+theorem preservation (t t' : Tm) (T : Ty)
383+    (hT : <{ ∅ ⊢ ~t ⦂ ~T }>) (hs : t ⟶ t') : <{ ∅ ⊢ ~t' ⦂ ~T }> := by
384+  generalize hΓ : (∅ : Context) = Γ at hT
385+  induction hT generalizing t' with
386+  | var => cases hs
387+  | abs => cases hs
388+  | tru => cases hs
389+  | fls => cases hs
390+  | app Γ T₁ T₂ t₁ t₂ h₁ h₂ ih₁ ih₂ =>
391+    subst hΓ
392+    cases hs with
393+    | appAbs _ _ _ _ _ =>
394+      -- The one interesting case: the desired result is the substitution lemma.
395+      cases h₁ with
396+      | abs _ _ _ _ _ hb => exact substitution_preserves_typing _ _ _ _ _ _ hb h₂
397+    | app1 _ t₁' _ h => exact .app _ _ _ _ _ (ih₁ t₁' h rfl) h₂
398+    | app2 _ _ t₂' _ h => exact .app _ _ _ _ _ h₁ (ih₂ t₂' h rfl)
399+  | ite Γ t₁ t₂ t₃ T₁ h₁ h₂ h₃ ih₁ ih₂ ih₃ =>
400+    subst hΓ
401+    cases hs with
402+    | ifTrue => exact h₂
403+    | ifFalse => exact h₃
404+    | ifStep _ t₁' _ _ h => exact .ite _ _ _ _ _ (ih₁ t₁' h rfl) h₂ h₃
405+
406+-- *Proof*: By induction on the derivation of `⊢ t ⦂ T`.
407+
408+-- - We can immediately rule out `HasType.var`, `HasType.abs`, `HasType.tru`,
409+--   and `HasType.fls` as final rules in the derivation, since in each of these
410+--   cases `t` cannot take a step.
411+
412+-- - If the last rule in the derivation is `HasType.app`, then `t = t₁ t₂`, and

414+--   two induction hypotheses: (1) `t₁ ⟶ t₁'` implies `⊢ t₁' ⦂ T₂→T` and (2)
415+--   `t₂ ⟶ t₂'` implies `⊢ t₂' ⦂ T₂`. There are now three subcases to consider,
416+--   one for each rule that could be used to show that `t₁ t₂` takes a step to
417+--   `t'`.

420+--     by the first IH, `t₁'` has the same type as `t₁` (`⊢ t₁' ⦂ T₂→T`), and
421+--     hence by `HasType.app` `t₁' t₂` has type `T`.

427+--     lemma.

431+--   `⊢ t₃ ⦂ T₁`, and with three induction hypotheses: (1) `t₁ ⟶ t₁'` implies
432+--   `⊢ t₁' ⦂ Bool`, (2) `t₂ ⟶ t₂'` implies `⊢ t₂' ⦂ T₁`, and (3) `t₃ ⟶ t₃'`

438+--     is immediate, since `t₂` and `t₃` have the same type as `t`.

440+--   - Otherwise, `t` steps by `Step.ifStep`, and the desired conclusion follows
441+--     directly from the first induction hypothesis.

509+-- ## Context Invariance (Optional)
510+
511+-- Another standard technical lemma associated with typed languages is
512+-- *context invariance*. It states that typing is preserved under "inessential
513+-- changes" to the context `Γ` — in particular, changes that do not affect any
514+-- of the free variables of the term. In this section, we establish this
515+-- property for our system, introducing some other standard terminology on the
516+-- way.
517+
518+-- First, we need to define the *free variables* in a term — i.e., variables
519+-- that are used in the term in positions that are *not* in the scope of an
520+-- enclosing function abstraction binding a variable of the same name.
521+
522+-- More technically, a variable `x` *appears free in* a term *t* if `t`
523+-- contains some occurrence of `x` that is not under an abstraction labeled
524+-- `x`. For example:
525+
526+-- - `y` appears free, but `x` does not, in `λx:T→U. x y`
527+-- - both `x` and `y` appear free in `(λx:T→U. x y) x`
528+-- - no variables appear free in `λx:T→U. λy:T. x y`
529+
530+-- We write this `x ∈ᶠ t`, reading the relation as "`x` is one of the free
531+-- variables of `t`". Formally:
532+
533+section
534+set_option hygiene false in
535+local infix:50 " ∈ᶠ " => AppearsFreeIn
536+
537+inductive AppearsFreeIn (x : String) : Tm → Prop where
538+  | var : x ∈ᶠ (Tm.var x)
539+  | app1 (t₁ t₂ : Tm) (h : x ∈ᶠ t₁) : x ∈ᶠ <{ ~t₁ ~t₂ }>
540+  | app2 (t₁ t₂ : Tm) (h : x ∈ᶠ t₂) : x ∈ᶠ <{ ~t₁ ~t₂ }>
541+  | abs (y : String) (T₁ : Ty) (t₁ : Tm) (hne : y ≠ x) (h : x ∈ᶠ t₁) :
542+      x ∈ᶠ <{ λ ~y : ~T₁ . ~t₁ }>
543+  | ite1 (t₁ t₂ t₃ : Tm) (h : x ∈ᶠ t₁) : x ∈ᶠ <{ if ~t₁ then ~t₂ else ~t₃ }>
544+  | ite2 (t₁ t₂ t₃ : Tm) (h : x ∈ᶠ t₂) : x ∈ᶠ <{ if ~t₁ then ~t₂ else ~t₃ }>
545+  | ite3 (t₁ t₂ t₃ : Tm) (h : x ∈ᶠ t₃) : x ∈ᶠ <{ if ~t₁ then ~t₂ else ~t₃ }>
546+end
547+
548+scoped infix:50 " ∈ᶠ " => AppearsFreeIn
549+
550+-- The *free variables* of a term are just the variables that appear free in
551+-- it. This gives us another way to define *closed* terms — arguably a better
552+-- one, since it applies even to ill-typed terms. Indeed, this is the standard
553+-- definition of the term "closed."
554+
555+def Tm.Closed (t : Tm) : Prop := ∀ x, ¬ x ∈ᶠ t
556+
557+-- Conversely, an *open* term is one that may contain free variables. (I.e.,
558+-- every term is an open term; the closed terms are a subset of the open ones.
559+-- "Open" precisely means "possibly containing free variables.")

582+    induction ha generalizing Γ T with

593+    | ite2 _ _ _ _ ih => cases hT with | ite _ _ _ _ _ _ h₂ _ => exact ih _ _ h₂
594+    | ite3 _ _ _ _ ih => cases hT with | ite _ _ _ _ _ _ _ h₃ => exact ih _ _ h₃

597+-- that, for all contexts `Γ`, if `t` is well typed under `Γ`, then `Γ`
598+-- assigns some type to `x`.

601+--   assumption that `t` is well typed under `Γ` we have immediately that `Γ`
602+--   assigns a type to `x`.
603+
604+-- - If the last rule used is `AppearsFreeIn.app1`, then `t = t₁ t₂` and `x`
605+--   appears free in `t₁`. Since `t` is well typed under `Γ`, we can see from
606+--   the typing rules that `t₁` must also be, and the IH then tells us that `Γ`
607+--   assigns `x` a type.

609+-- - Almost all the other cases are similar: `x` appears free in a subterm of
610+--   `t`, and since `t` is well typed under `Γ`, we know the subterm of `t` in
611+--   which `x` appears is well typed under `Γ` as well, and the IH gives us
612+--   exactly the conclusion we want.
613+
614+-- - The only remaining case is `AppearsFreeIn.abs`. In this case
615+--   `t = λy:T₁. t₁` and `x` appears free in `t₁`, and we also know that `x` is
616+--   different from `y`. The difference from the previous cases is that, whereas
617+--   `t` is well typed under `Γ`, its body `t₁` is well typed under `y ↦ T₁; Γ`,
618+--   so the IH allows us to conclude that `x` is assigned some type by the

620+--   we appeal to lemma `PartialMap.update_neq`, noting that `x` and `y` are

640+-- Finally, we establish *context invariance*. It is useful in cases when we
641+-- have a proof of some typing relation `Γ ⊢ t ⦂ T`, and we need to replace
642+-- `Γ` by a different context `Γ'`. When is it safe to do this? Intuitively,
643+-- it must at least be the case that `Γ'` assigns the same types as `Γ` to all
644+-- the variables that appear free in `t`. In fact, this is the only condition
645+-- that is needed.
646+
647+theorem context_invariance (Γ Γ' : Context) (t : Tm) (T : Ty)
648+    (hT : <{ ~Γ ⊢ ~t ⦂ ~T }>) (hf : ∀ x, x ∈ᶠ t → Γ[x] = Γ'[x]) :
649+    <{ ~Γ' ⊢ ~t ⦂ ~T }> := by
650+  all_goals
651+    induction hT generalizing Γ' with
652+    | var _ x _ h => exact .var _ x _ ((hf x .var) ▸ h)
653+    | abs _ y _ _ _ _ ih =>
654+      refine .abs _ _ _ _ _ (ih _ ?_)
655+      intro z hz
656+      by_cases hyz : y = z
657+      · subst hyz; rw [PartialMap.update_eq, PartialMap.update_eq]
658+      -- The only tricky step.
659+      · rw [PartialMap.update_neq _ _ _ hyz, PartialMap.update_neq _ _ _ hyz]
660+        exact hf z (.abs y _ _ hyz hz)
661+    | app _ _ _ t₁ t₂ _ _ ih₁ ih₂ =>
662+      exact .app _ _ _ _ _ (ih₁ _ (fun z hz => hf z (.app1 t₁ t₂ hz)))
663+                           (ih₂ _ (fun z hz => hf z (.app2 t₁ t₂ hz)))
664+    | tru => exact .tru _
665+    | fls => exact .fls _
666+    | ite _ t₁ t₂ t₃ _ _ _ _ ih₁ ih₂ ih₃ =>
667+      exact .ite _ _ _ _ _ (ih₁ _ (fun z hz => hf z (.ite1 t₁ t₂ t₃ hz)))
668+                           (ih₂ _ (fun z hz => hf z (.ite2 t₁ t₂ t₃ hz)))
669+                           (ih₃ _ (fun z hz => hf z (.ite3 t₁ t₂ t₃ hz)))
670+
671+-- *Proof*: By induction on the derivation of `Γ ⊢ t ⦂ T`.
672+
673+-- - If the last rule in the derivation was `HasType.var`, then `t = x` and
674+--   `Γ x = T`. By assumption, `Γ' x = T` as well, and hence `Γ' ⊢ t ⦂ T` by
675+--   `HasType.var`.
676+
677+-- - If the last rule was `HasType.abs`, then `t = λy:T₂. t₁`, with
678+--   `T = T₂ → T₁` and `y ↦ T₂; Γ ⊢ t₁ ⦂ T₁`. The induction hypothesis states
679+--   that for any context `Γ''`, if `y ↦ T₂; Γ` and `Γ''` assign the same types
680+--   to all the free variables in `t₁`, then `t₁` has type `T₁` under `Γ''`. Let
681+--   `Γ'` be a context which agrees with `Γ` on the free variables in `t`; we
682+--   must show `Γ' ⊢ λy:T₂. t₁ ⦂ T₂ → T₁`.
683+
684+--   By `HasType.abs`, it suffices to show that `y ↦ T₂; Γ' ⊢ t₁ ⦂ T₁`. By the
685+--   IH (setting `Γ'' = y ↦ T₂;Γ'`), it suffices to show that `y ↦ T₂;Γ` and
686+--   `y ↦ T₂;Γ'` agree on all the variables that appear free in `t₁`.
687+
688+--   Any variable occurring free in `t₁` must be either `y` or some other
689+--   variable. `y ↦ T₂; Γ` and `y ↦ T₂; Γ'` clearly agree on `y`. Otherwise,
690+--   note that any variable other than `y` that occurs free in `t₁` also occurs
691+--   free in `t = λy:T₂. t₁`, and by assumption `Γ` and `Γ'` agree on all such
692+--   variables; hence so do `y ↦ T₂; Γ` and `y ↦ T₂; Γ'`.
693+
694+-- - If the last rule was `HasType.app`, then `t = t₁ t₂`, with
695+--   `Γ ⊢ t₁ ⦂ T₂ → T` and `Γ ⊢ t₂ ⦂ T₂`. One induction hypothesis states that
696+--   for all contexts `Γ'`, if `Γ'` agrees with `Γ` on the free variables in
697+--   `t₁`, then `t₁` has type `T₂ → T` under `Γ'`; there is a similar IH for
698+--   `t₂`. We must show that `t₁ t₂` also has type `T` under `Γ'`, given the
699+--   assumption that `Γ'` agrees with `Γ` on all the free variables in `t₁ t₂`.
700+--   By `HasType.app`, it suffices to show that `t₁` and `t₂` each have the same
701+--   type under `Γ'` as under `Γ`. But all free variables in `t₁` are also free
702+--   in `t₁ t₂`, and similarly for `t₂`; hence the desired result follows from
703+--   the induction hypotheses.

935+-- constants and primitive operators.
936+

938+-- numeric constants and multiplication — together with the successor,
939+-- predecessor, and zero-test operations of the Types chapter. What is new is
940+-- the setting: those operations now live in a language that also has
941+-- variables, abstraction, and application, so an arithmetic computation can
942+-- be packaged up as a function and passed around as a value.

954+-- predecessor, multiplication, and zero-testing.

967+-- an extension of it, so it needs its own concrete syntax. Rather than invent
968+-- a new one, we reuse the grammars set up in the Stlc chapter — the syntax
969+-- categories `stlcTy`, `stlcTm`, and `stlcVar` — and give them a new meaning
970+-- here. Terms and types of this language are therefore written inside the
971+-- same `<{ … }>` brackets, with the same `~e` escape back to Lean.

973+-- _Details:_ Notation encoding: types
974+
975+-- The type grammar needs no new productions: `Nat` is a bare identifier,
976+-- which the template already accepts, and arrows and parentheses are
977+-- unchanged. Only the `macro_rules` are new, and they differ from the STLC's
978+-- in just two places — the identifier `Nat` names this language's base type,
979+-- and the arrow builds this language's `StlcArith.Ty.arrow`.

996+-- right, so `x * y * z` is `x * (y * z)`.

1001+-- they are written as though they were functions applied to an argument,
1002+-- `succ t`, and the application rule below recognizes them. `if0` **is** a
