65added-- ## Progress
66added
67added-- The *progress* theorem tells us that closed, well-typed terms are not
68added-- stuck: either a well-typed term is a value, or it can take a reduction
69added-- step. The proof is a relatively straightforward extension of the progress
70added-- proof we saw in the Types chapter. We give the proof in English first, then
71added-- the formal version.
72added
73addedtheorem progress (t : Tm) (T : Ty) (hT : <{ ∅ ⊢ ~t ⦂ ~T }>) :
74added t.IsValue ∨ ∃ t', t ⟶ t' := by
75added generalize hΓ : (∅ : Context) = Γ at hT
76added induction hT with
77added | var Γ x T₁ h =>
78added subst hΓ
79added -- Contradictory: variables cannot be typed in an empty context.
80added rw [PartialMap.apply_empty] at h
81added cases h
82added | abs => exact .inl (.abs ..)
83added | tru => exact .inl .tru
84added | fls => exact .inl .fls
85added | app Γ T₁ T₂ t₁ t₂ h₁ h₂ ih₁ ih₂ =>
86added -- `t = t₁ t₂`. Proceed by cases on whether `t₁` is a value or steps.
87added right
88added cases ih₁ hΓ with
89added | inl hv₁ =>
90added cases ih₂ hΓ with
91added | inl hv₂ =>
92added obtain ⟨x, u, rfl⟩ := canonical_forms_fun t₁ _ _ (hΓ ▸ h₁) hv₁
93added exact ⟨<{ [~x := ~t₂] ~u }>, .appAbs x T₂ u t₂ hv₂⟩
94added | inr hs₂ => obtain ⟨t₂', h⟩ := hs₂; exact ⟨<{ ~t₁ ~t₂' }>, .app2 t₁ t₂ t₂' hv₁ h⟩
95added | inr hs₁ => obtain ⟨t₁', h⟩ := hs₁; exact ⟨<{ ~t₁' ~t₂ }>, .app1 t₁ t₁' t₂ h⟩
96added | ite Γ t₁ t₂ t₃ T₁ h₁ h₂ h₃ ih₁ ih₂ ih₃ =>
97added right
98added cases ih₁ hΓ with
99added | inl hv₁ =>
100added cases canonical_forms_bool t₁ (hΓ ▸ h₁) hv₁ with
101added | inl he => subst he; exact ⟨t₂, .ifTrue t₂ t₃⟩
102added | inr he => subst he; exact ⟨t₃, .ifFalse t₂ t₃⟩
103added | inr hs₁ =>
104added obtain ⟨t₁', h⟩ := hs₁
105added exact ⟨<{ if ~t₁' then ~t₂ else ~t₃ }>, .ifStep t₁ t₁' t₂ t₃ h⟩
106added
107added-- *Proof*: By induction on the derivation of `⊢ t ⦂ T`.
108added
109added-- - The last rule of the derivation cannot be `HasType.var`, since a variable
110added-- is never well typed in an empty context.
111added
112added-- - The `HasType.tru`, `HasType.fls`, and `HasType.abs` cases are trivial,
113added-- since in each of these cases we can see by inspecting the rule that `t` is
114added-- a value.
115added
116added-- - If the last rule of the derivation is `HasType.app`, then `t` has the form
117added-- `t₁ t₂` for some `t₁` and `t₂`, where `⊢ t₁ ⦂ T₂ → T` and `⊢ t₂ ⦂ T₂` for
118added-- some type `T₂`. The induction hypothesis for the first subderivation says
119added-- that either `t₁` is a value or else it can take a reduction step.
120added
121added-- - If `t₁` is a value, then consider `t₂`, which by the induction hypothesis
122added-- for the second subderivation must also either be a value or take a step.
123added
124added-- - Suppose `t₂` is a value. Since `t₁` is a value with an arrow type, it must
125added-- be a lambda abstraction; hence `t₁ t₂` can take a step by `Step.appAbs`.
126added
127added-- - Otherwise, `t₂` can take a step, and hence so can `t₁ t₂` by `Step.app2`.
128added
129added-- - If `t₁` can take a step, then so can `t₁ t₂` by `Step.app1`.
130added
131added-- - If the last rule of the derivation is `HasType.ite`, then
132added-- `t = if t₁ then t₂ else t₃`, where `t₁` has type `Bool`. The first IH says
133added-- that `t₁` either is a value or takes a step.
134added
135added-- - If `t₁` is a value, then since it has type `Bool` it must be either `true`
136added-- or `false`. If it is `true`, then `t` steps to `t₂`; otherwise it steps to
137added-- `t₃`.
138added
139added-- - Otherwise, `t₁` takes a step, and therefore so does `t` (by `Step.ifStep`).

150added-- ## Preservation
151added
152added-- The other half of the type soundness property is the preservation of types
153added-- during reduction. For this part, we'll need to develop some technical
154added-- machinery for reasoning about variables and substitution. Working from top
155added-- to bottom (from the high-level property we are actually interested in to
156added-- the lowest-level technical lemmas that are needed by various cases of the
157added-- more interesting proofs), the story goes like this:
158added
159added-- - The *preservation theorem* is proved by induction on a typing derivation
160added-- and case analysis on the step relation, pretty much as we did in the Types
161added-- chapter. The one case that is significantly different is the one for the
162added-- `Step.appAbs` rule, whose definition uses the substitution operation. To
163added-- see that this step preserves typing, we need to know that the substitution
164added-- itself does. So we prove a...
165added
166added-- - *substitution lemma*, stating that substituting a (closed, well-typed) term
167added-- `s` for a variable `x` in a term `t` preserves the type of `t`. The proof
168added-- goes by induction on the form of `t` and requires looking at all the
169added-- different cases in the definition of substitition. This time, for the
170added-- variables case, we discover that we need to deduce from the fact that a
171added-- term `s` has type S in the empty context the fact that `s` has type S in
172added-- every context. For this we prove a...
173added
174added-- - *weakening* lemma, showing that typing is preserved under "extensions" to
175added-- the context `Γ`.
176added
177added-- To make Lean happy, though, we need to formalize the story in the opposite
178added-- order, starting with weakening...
179added
180added-- ### The Weakening Lemma
181added
182added-- First, we show that typing is preserved under "extensions" to the context
183added-- `Γ`. (Recall map inclusion, `Γ ⊆ Γ'`, from the `Typeclasses` chapter.)
184added
185addedtheorem weakening (Γ Γ' : Context) (t : Tm) (T : Ty)
186added (hi : Γ ⊆ Γ') (hT : <{ ~Γ ⊢ ~t ⦂ ~T }>) : <{ ~Γ' ⊢ ~t ⦂ ~T }> := by
187added induction hT generalizing Γ' with
188added | var _ x _ h => exact .var _ x _ (hi x _ h)
189added | abs _ x _ _ _ _ ih => exact .abs _ x _ _ _ (ih _ (PartialMap.update_subset _ _ _ _ hi))
190added | app _ _ _ _ _ _ _ ih₁ ih₂ => exact .app _ _ _ _ _ (ih₁ _ hi) (ih₂ _ hi)
191added | tru => exact .tru _
192added | fls => exact .fls _
193added | ite _ _ _ _ _ _ _ _ ih₁ ih₂ ih₃ => exact .ite _ _ _ _ _ (ih₁ _ hi) (ih₂ _ hi) (ih₃ _ hi)

195added-- The following simple corollary is what we actually need below.
196added
197addedtheorem weakening_empty (Γ : Context) (t : Tm) (T : Ty) (hT : <{ ∅ ⊢ ~t ⦂ ~T }>) :
198added <{ ~Γ ⊢ ~t ⦂ ~T }> :=

202added-- ### The Substitution Lemma
203added
204added-- Now we come to the conceptual heart of the proof that reduction preserves
205added-- types — namely, the observation that *substitution* preserves types.
206added
207added-- Formally, the so-called *substitution lemma* says this: Suppose we have a
208added-- term `t` with a free variable `x`, and suppose we've assigned a type `T` to
209added-- `t` under the assumption that `x` has some type `U`. Also, suppose that we
210added-- have some other term `v` and that we've shown that `v` has type `U`. Then,
211added-- since `v` satisfies the assumption we made about `x` when typing `t`, we
212added-- can substitute `v` for each of the occurrences of `x` in `t` and obtain a
213added-- new term that still has type `T`.
214added
215addedtheorem substitution_preserves_typing (Γ : Context) (x : String) (U : Ty)
216added (t v : Tm) (T : Ty)
217added (hT : <{ ~x ↦ ~U ; ~Γ ⊢ ~t ⦂ ~T }>) (hv : <{ ∅ ⊢ ~v ⦂ ~U }>) :
218added <{ ~Γ ⊢ [~x := ~v] ~t ⦂ ~T }> := by
219added -- By induction on `t`; in each case we get at the derivation of `hT`.
220added induction t generalizing Γ T with
221added | var y =>
222added cases hT with
223added | var _ _ _ h =>
224added by_cases hxy : x = y
225added · subst hxy
226added rw [PartialMap.update_eq] at h
227added rw [subst_var_eq]
228added have hUT : U = T := Option.some.inj h
229added subst hUT
230added exact weakening_empty _ _ _ hv
231added · rw [PartialMap.update_neq _ _ _ hxy] at h
232added rw [subst_var_ne _ _ _ hxy]
233added exact .var _ y _ h
234added | app t₁ t₂ ih₁ ih₂ =>
235added cases hT with
236added | app _ _ _ _ _ h₁ h₂ => rw [subst_app]; exact .app _ _ _ _ _ (ih₁ _ _ h₁) (ih₂ _ _ h₂)
237added | abs y S t₁ ih =>
238added cases hT with
239added | abs _ _ _ _ _ h =>
240added by_cases hxy : x = y
241added · subst hxy
242added rw [subst_abs_eq]
243added rw [PartialMap.update_shadow] at h
244added exact .abs _ _ _ _ _ h
245added · rw [subst_abs_ne _ _ _ _ _ hxy]
246added rw [PartialMap.update_permute _ _ _ _ _ (Ne.symm hxy)] at h
247added exact .abs _ _ _ _ _ (ih _ _ h)
248added | tru => cases hT with | tru => rw [subst_tru]; exact .tru _
249added | fls => cases hT with | fls => rw [subst_fls]; exact .fls _
250added | ite c t e ihc iht ihe =>
251added cases hT with
252added | ite _ _ _ _ _ h₁ h₂ h₃ =>
253added rw [subst_ite]
254added exact .ite _ _ _ _ _ (ihc _ _ h₁) (iht _ _ h₂) (ihe _ _ h₃)
255added
256added-- The substitution lemma can be viewed as a kind of "commutation property."
257added-- Intuitively, it says that substitution and typing can be done in either
258added-- order: we can either assign types to the terms `t` and `v` separately
259added-- (under suitable contexts) and then combine them using substitution, or we
260added-- can substitute first and then assign a type to ` `x:=v` t`; the result is
261added-- the same either way.
262added
263added-- *Proof*: We show, by induction on `t`, that for all `T` and `Γ`, if
264added-- `x ↦ U; Γ ⊢ t ⦂ T` and `⊢ v ⦂ U`, then `Γ ⊢ [x:=v]t ⦂ T`.
265added
266added-- - If `t` is a variable there are two cases to consider, depending on whether
267added-- `t` is `x` or some other variable.
268added
269added-- - If `t = x`, then from the fact that `x ↦ U; Γ ⊢ x ⦂ T` we conclude that
270added-- `U = T`. We must show that `[x:=v]x = v` has type `T` under `Γ`, given the
271added-- assumption that `v` has type `U = T` under the empty context. This follows
272added-- from the weakening lemma.
273added
274added-- - If `t` is some variable `y` that is not equal to `x`, then we need only
275added-- note that `y` has the same type under `x ↦ U; Γ` as under `Γ`.
276added
277added-- - If `t` is an abstraction `λy:S. t₀`, then `T = S→T₁` and the IH tells us,
278added-- for all `Γ'` and `T₀`, that if `x ↦ U; Γ' ⊢ t₀ ⦂ T₀`, then
279added-- `Γ' ⊢ [x:=v]t₀ ⦂ T₀`. Moreover, by inspecting the typing rules we see it
280added-- must be the case that `y ↦ S; x ↦ U; Γ ⊢ t₀ ⦂ T₁`.
281added
282added-- The substitution in the conclusion behaves differently depending on whether
283added-- `x` and `y` are the same variable.
284added
285added-- First, suppose `x = y`. Then, by the definition of substitution,
286added-- `[x:=v]t = t`, so we just need to show `Γ ⊢ t ⦂ T`. Using `HasType.abs`, we
287added-- need to show that `y ↦ S; Γ ⊢ t₀ ⦂ T₁`. But we know
288added-- `y ↦ S; x ↦ U; Γ ⊢ t₀ ⦂ T₁`, and the claim follows since `x = y`.
289added
290added-- Second, suppose `x <> y`. Again, using `HasType.abs`, we need to show that
291added-- `y ↦ S; Γ ⊢ [x:=v]t₀ ⦂ T₁`. Since `x <> y`, we have
292added-- `y ↦ S; x ↦ U; Γ = x ↦ U; y ↦ S; Γ`. So we have
293added-- `x ↦ U; y ↦ S; Γ ⊢ t₀ ⦂ T₁`. Then, the the IH applies (taking
294added-- `Γ' = y ↦ S; Γ`), giving us `y ↦ S; Γ ⊢ [x:=v]t₀ ⦂ T₁`, as required.
295added
296added-- - If `t` is an application `t₁ t₂`, the result follows straightforwardly from
297added-- the definition of substitution and the induction hypotheses.
298added
299added-- - The remaining cases are similar to the application case.
300added
301added-- One technical subtlety in the statement of the above lemma is that we
302added-- assume `v` has type `U` in the *empty* context — in other words, we assume
303added-- `v` is closed. (Since we are using a simple definition of substition that
304added-- is not capture-avoiding, it doesn't make sense to substitute non-closed
305added-- terms into other terms. Fortunately, closed terms are all we need!)
306added

318added-- ### Main Theorem
319added
320added-- We now have the ingredients we need to prove preservation: if a closed,
321added-- well-typed term `t` has type `T` and takes a step to `t'`, then `t'` is
322added-- also a closed term with type `T`. In other words, the small-step reduction
323added-- relation preserves types.
324added
325addedtheorem preservation (t t' : Tm) (T : Ty)
326added (hT : <{ ∅ ⊢ ~t ⦂ ~T }>) (hs : t ⟶ t') : <{ ∅ ⊢ ~t' ⦂ ~T }> := by
327added generalize hΓ : (∅ : Context) = Γ at hT
328added induction hT generalizing t' with
329added | var => cases hs
330added | abs => cases hs
331added | tru => cases hs
332added | fls => cases hs
333added | app Γ T₁ T₂ t₁ t₂ h₁ h₂ ih₁ ih₂ =>
334added subst hΓ
335added cases hs with
336added | appAbs _ _ _ _ _ =>
337added -- The one interesting case: the desired result is the substitution lemma.
338added cases h₁ with
339added | abs _ _ _ _ _ hb => exact substitution_preserves_typing _ _ _ _ _ _ hb h₂
340added | app1 _ t₁' _ h => exact .app _ _ _ _ _ (ih₁ t₁' h rfl) h₂
341added | app2 _ _ t₂' _ h => exact .app _ _ _ _ _ h₁ (ih₂ t₂' h rfl)
342added | ite Γ t₁ t₂ t₃ T₁ h₁ h₂ h₃ ih₁ ih₂ ih₃ =>
343added subst hΓ
344added cases hs with
345added | ifTrue => exact h₂
346added | ifFalse => exact h₃
347added | ifStep _ t₁' _ _ h => exact .ite _ _ _ _ _ (ih₁ t₁' h rfl) h₂ h₃
348added
349added-- *Proof*: By induction on the derivation of `⊢ t ⦂ T`.
350added
351added-- - We can immediately rule out `HasType.var`, `HasType.abs`, `HasType.tru`,
352added-- and `HasType.fls` as final rules in the derivation, since in each of these
353added-- cases `t` cannot take a step.
354added
355added-- - If the last rule in the derivation is `HasType.app`, then `t = t₁ t₂`, and
356added-- there are subderivations showing that `⊢ t₁ ⦂ T₂→T` and `⊢ t₂ ⦂ T₂` plus
357added-- two induction hypotheses: (1) `t₁ ⟶ t₁'` implies `⊢ t₁' ⦂ T₂→T` and (2)
358added-- `t₂ ⟶ t₂'` implies `⊢ t₂' ⦂ T₂`. There are now three subcases to consider,
359added-- one for each rule that could be used to show that `t₁ t₂` takes a step to
360added-- `t'`.
361added
362added-- - If `t₁ t₂` takes a step by `Step.app1`, with `t₁` stepping to `t₁'`, then,
363added-- by the first IH, `t₁'` has the same type as `t₁` (`⊢ t₁' ⦂ T₂→T`), and
364added-- hence by `HasType.app` `t₁' t₂` has type `T`.
365added
366added-- - The `Step.app2` case is similar, using the second IH.
367added
368added-- - If `t₁ t₂` takes a step by `Step.appAbs`, then `t₁ = λx:T₀. t₀` and `t₁ t₂`
369added-- steps to `[x0:=t₂]t₀`; the desired result now follows from the substitution
370added-- lemma.
371added
372added-- - If the last rule in the derivation is `HasType.ite`, then
373added-- `t = if t₁ then t₂ else t₃`, with `⊢ t₁ ⦂ Bool`, `⊢ t₂ ⦂ T₁`, and
374added-- `⊢ t₃ ⦂ T₁`, and with three induction hypotheses: (1) `t₁ ⟶ t₁'` implies
375added-- `⊢ t₁' ⦂ Bool`, (2) `t₂ ⟶ t₂'` implies `⊢ t₂' ⦂ T₁`, and (3) `t₃ ⟶ t₃'`
376added-- implies `⊢ t₃' ⦂ T₁`.
377added
378added-- There are again three subcases to consider, depending on how `t` steps.
379added
380added-- - If `t` steps to `t₂` or `t₃` by `Step.ifTrue` or `Step.ifFalse`, the result
381added-- is immediate, since `t₂` and `t₃` have the same type as `t`.
382added
383added-- - Otherwise, `t` steps by `Step.ifStep`, and the desired conclusion follows
384added-- directly from the first induction hypothesis.

427added-- Another standard technical lemma associated with typed languages is
428added-- *context invariance*. It states that typing is preserved under "inessential
429added-- changes" to the context `Γ` — in particular, changes that do not affect any
430added-- of the free variables of the term. In this section, we establish this
431added-- property for our system, introducing some other standard terminology on the
432added-- way.
433added
434added-- First, we need to define the *free variables* in a term — i.e., variables
435added-- that are used in the term in positions that are *not* in the scope of an
436added-- enclosing function abstraction binding a variable of the same name.
437added
438added-- More technically, a variable `x` *appears free in* a term *t* if `t`
439added-- contains some occurrence of `x` that is not under an abstraction labeled
440added-- `x`. For example:
441added
442added-- - `y` appears free, but `x` does not, in `λx:T→U. x y`
443added-- - both `x` and `y` appear free in `(λx:T→U. x y) x`
444added-- - no variables appear free in `λx:T→U. λy:T. x y`
445added
446added-- We write this `x ∈ᶠ t`, reading the relation as "`x` is one of the free
447added-- variables of `t`". Formally:
448added
449addedsection
450addedset_option hygiene false in
451addedlocal infix:50 " ∈ᶠ " => AppearsFreeIn
452added
453addedinductive AppearsFreeIn (x : String) : Tm → Prop where
454added | var : x ∈ᶠ (Tm.var x)
455added | app1 (t₁ t₂ : Tm) (h : x ∈ᶠ t₁) : x ∈ᶠ <{ ~t₁ ~t₂ }>
456added | app2 (t₁ t₂ : Tm) (h : x ∈ᶠ t₂) : x ∈ᶠ <{ ~t₁ ~t₂ }>
457added | abs (y : String) (T₁ : Ty) (t₁ : Tm) (hne : y ≠ x) (h : x ∈ᶠ t₁) :
458added x ∈ᶠ <{ λ ~y : ~T₁ . ~t₁ }>
459added | ite1 (t₁ t₂ t₃ : Tm) (h : x ∈ᶠ t₁) : x ∈ᶠ <{ if ~t₁ then ~t₂ else ~t₃ }>
460added | ite2 (t₁ t₂ t₃ : Tm) (h : x ∈ᶠ t₂) : x ∈ᶠ <{ if ~t₁ then ~t₂ else ~t₃ }>
461added | ite3 (t₁ t₂ t₃ : Tm) (h : x ∈ᶠ t₃) : x ∈ᶠ <{ if ~t₁ then ~t₂ else ~t₃ }>
462addedend

466added-- The *free variables* of a term are just the variables that appear free in
467added-- it. This gives us another way to define *closed* terms — arguably a better
468added-- one, since it applies even to ill-typed terms. Indeed, this is the standard
469added-- definition of the term "closed."
470added
471addeddef Tm.Closed (t : Tm) : Prop := ∀ x, ¬ x ∈ᶠ t

474added-- every term is an open term; the closed terms are a subset of the open ones.
475added-- "Open" precisely means "possibly containing free variables.")

535added-- Finally, we establish *context invariance*. It is useful in cases when we
536added-- have a proof of some typing relation `Γ ⊢ t ⦂ T`, and we need to replace
537added-- `Γ` by a different context `Γ'`. When is it safe to do this? Intuitively,
538added-- it must at least be the case that `Γ'` assigns the same types as `Γ` to all
539added-- the variables that appear free in `t`. In fact, this is the only condition
540added-- that is needed.
541added
542addedtheorem context_invariance (Γ Γ' : Context) (t : Tm) (T : Ty)
543added (hT : <{ ~Γ ⊢ ~t ⦂ ~T }>) (hf : ∀ x, x ∈ᶠ t → Γ[x] = Γ'[x]) :
544added <{ ~Γ' ⊢ ~t ⦂ ~T }> := by
545added sorry
546added
547added-- *Proof*: By induction on the derivation of `Γ ⊢ t ⦂ T`.
548added
549added-- - If the last rule in the derivation was `HasType.var`, then `t = x` and
550added-- `Γ x = T`. By assumption, `Γ' x = T` as well, and hence `Γ' ⊢ t ⦂ T` by
551added-- `HasType.var`.
552added
553added-- - If the last rule was `HasType.abs`, then `t = λy:T₂. t₁`, with
554added-- `T = T₂ → T₁` and `y ↦ T₂; Γ ⊢ t₁ ⦂ T₁`. The induction hypothesis states
555added-- that for any context `Γ''`, if `y ↦ T₂; Γ` and `Γ''` assign the same types
556added-- to all the free variables in `t₁`, then `t₁` has type `T₁` under `Γ''`. Let
557added-- `Γ'` be a context which agrees with `Γ` on the free variables in `t`; we
558added-- must show `Γ' ⊢ λy:T₂. t₁ ⦂ T₂ → T₁`.
559added
560added-- By `HasType.abs`, it suffices to show that `y ↦ T₂; Γ' ⊢ t₁ ⦂ T₁`. By the
561added-- IH (setting `Γ'' = y ↦ T₂;Γ'`), it suffices to show that `y ↦ T₂;Γ` and
562added-- `y ↦ T₂;Γ'` agree on all the variables that appear free in `t₁`.
563added
564added-- Any variable occurring free in `t₁` must be either `y` or some other
565added-- variable. `y ↦ T₂; Γ` and `y ↦ T₂; Γ'` clearly agree on `y`. Otherwise,
566added-- note that any variable other than `y` that occurs free in `t₁` also occurs
567added-- free in `t = λy:T₂. t₁`, and by assumption `Γ` and `Γ'` agree on all such
568added-- variables; hence so do `y ↦ T₂; Γ` and `y ↦ T₂; Γ'`.
569added
570added-- - If the last rule was `HasType.app`, then `t = t₁ t₂`, with
571added-- `Γ ⊢ t₁ ⦂ T₂ → T` and `Γ ⊢ t₂ ⦂ T₂`. One induction hypothesis states that
572added-- for all contexts `Γ'`, if `Γ'` agrees with `Γ` on the free variables in
573added-- `t₁`, then `t₁` has type `T₂ → T` under `Γ'`; there is a similar IH for
574added-- `t₂`. We must show that `t₁ t₂` also has type `T` under `Γ'`, given the
575added-- assumption that `Γ'` agrees with `Γ` on all the free variables in `t₁ t₂`.
576added-- By `HasType.app`, it suffices to show that `t₁` and `t₂` each have the same
577added-- type under `Γ'` as under `Γ`. But all free variables in `t₁` are also free
578added-- in `t₁ t₂`, and similarly for `t₂`; hence the desired result follows from
579added-- the induction hypotheses.
