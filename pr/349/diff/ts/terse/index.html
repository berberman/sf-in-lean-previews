6+--  # MoreStlc: More on the Simply Typed Lambda-Calculus
7+
8+--  ## Simple Extensions to STLC
9+
10+--  The simply typed lambda-calculus has a rich enough
11+--  structure to make its theoretical properties
12+--  interesting, but it is not much of a programming
13+--  language!
14+--
15+--  In this chapter, we begin to close the gap with
16+--  real-world languages by introducing a number of familiar
17+--  features that have straightforward treatments at the
18+--  level of typing.
19+
20+--  ### Numbers
21+
22+--  Adding types, constants, and primitive operations for
23+--  natural numbers is easy (as we saw in the `StlcExtended`
24+--  exercises).
25+
26+--  A more interesting extension... let-bindings.
27+--
28+--  When writing a complex expression, it is often useful to
29+--  give names to some of its subexpressions: this avoids
30+--  repetition and often increases readability.
31+
32+--  Syntax:
33+--
34+--        t ::=                   Terms
35+--            | ...                 (other terms same as before)
36+--            | let x = t₁ in t₂    let-binding
37+--
38+--  Reduction:
39+--
40+--                                       t₁ ⟶ t₁'
41+--                           -------------------------------------        (let₁)
42+--                           let x = t₁ in t₂ ⟶ let x = t₁' in t₂
43+--
44+--                              ---------------------------------         (letValue)
45+--                              let x = v₁ in t₂ ⟶ [x := v₁] t₂
46+--
47+--  Typing:
48+--
49+--                   Γ ⊢ t₁ ⦂ τ₁      x ↦ τ₁ ; Γ ⊢ t₂ ⦂ τ₂
50+--                   -------------------------------------------      (let)
51+--                           Γ ⊢ let x = t₁ in t₂ ⦂ τ₂
52+
53+--  ### Pairs
54+
55+--  In Lean, there are two ways of extracting the components
56+--  of a pair: *pattern matching* and the projection
57+--  operators `fst` and `snd`. Just for fun, let's do our
58+--  pairs the latter way. For example, here's how we'd write
59+--  a function that takes a pair of numbers and returns the
60+--  pair of their sum and difference:
61+--
62+--             λx : Nat × Nat.
63+--                let sum = fst x + snd x in
64+--                let diff = fst x - snd x in
65+--                (sum, diff)
66+--
67+--  Syntax:
68+--
69+--             t ::=                Terms
70+--                 | ...
71+--                 | (t₁, t₂)         pair
72+--                 | fst t            first projection
73+--                 | snd t            second projection
74+--
75+--             v ::=                Values
76+--                 | ...
77+--                 | (v₁, v₂)         pair value
78+--
79+--             τ ::=                Types
80+--                 | ...
81+--                 | τ₁ × τ₂          product type
82+
83+--  Reduction...
84+
85+--                                    t₁ ⟶ t₁'
86+--                               --------------------                        (pair₁)
87+--                               (t₁,t₂) ⟶ (t₁',t₂)
88+--
89+--                                    t₂ ⟶ t₂'
90+--                               --------------------                        (pair₂)
91+--                               (v₁,t₂) ⟶ (v₁,t₂')
92+--
93+--                                     t ⟶ t'
94+--                                 ------------------                        (fst₁)
95+--                                 fst t ⟶ fst t'
96+--
97+--                                ------------------                       (fstPair)
98+--                                 fst (v₁,v₂) ⟶ v₁
99+--
100+--                                     t ⟶ t'
101+--                                 ------------------                      (snd₁)
102+--                                 snd t ⟶ snd t'
103+--
104+--                                ------------------                       (sndPair)
105+--                                snd (v₁,v₂) ⟶ v₂
106+
107+--  Typing:
108+
109+--                           Γ ⊢ t₁ ⦂ τ₁     Γ t₂ ⦂ τ₂
110+--                          ------------------------------              (pair)
111+--                            Γ ⊢(t₁, t₂) ⦂ τ₁ × τ₂
112+--
113+--                                 Γ ⊢ t ⦂ τ₁ × τ₂
114+--                              -----------------------                  (fst)
115+--                                  Γ ⊢ fst t ⦂ τ₁
116+--
117+--                                  Γ ⊢ t ⦂ τ₁ × τ₂
118+--                              -----------------------                   (snd)
119+--                                   Γ ⊢ snd t ⦂ τ₂

156+--  ### Sums
157+
158+--  Many programs need to deal with values that can take two
159+--  distinct forms. For example, we might identify students
160+--  in a university database using *either* their name *or*
161+--  their id number. A search function might return *either*
162+--  a matching value *or* an error code.
163+--
164+--  These are specific examples of a binary *sum type*
165+--  (sometimes called a *disjoint union*), which describes a
166+--  set of values drawn from one of two given types, e.g.:
167+--
168+--             Nat + Bool
169+
170+--  We create elements of these types by tagging elements of
171+--  the component types, telling on which side of the sum we
172+--  are putting them. E.g.,
173+--
174+--         inl 42   ⦂ Nat + Bool
175+--         inr true ⦂ Nat + Bool
176+
177+--  In general, the elements of a type `τ₁ + τ₂` consist of
178+--  the elements of `τ₁` tagged with the token `inl`, plus
179+--  the elements of `τ₂` tagged with `inr`.
180+--
181+--  (As we've seen in Lean programming, one important use of
182+--  sums is signaling errors:
183+--
184+--            div ⦂ Nat → Nat → (Nat + Unit)
185+--            div =
186+--              λx:Nat. λy:Nat,
187+--                if iszero y then
188+--                  inr unit
189+--                else
190+--                  inl ...
191+
192+--  Values of sum type are "destructed" by case analysis:
193+
194+--          getNat ⦂ Nat+Bool → Nat
195+--          getNat =
196+--            λx:Nat+Bool,
197+--              case x of
198+--                inl n => n
199+--              | inr b => if b then 1 else 0
200+--
201+--  More formally...
202+--
203+--  Syntax:
204+--
205+--             t ::=                Terms
206+--                 | ...               (other terms same as before)
207+--                 | inl τ₂ t₁         tagging (left)
208+--                 | inr τ₁ t₂         tagging (right)
209+--                 | case t of         case analysis
210+--                     inl x₁ => t₁
211+--                   | inr x₂ => t₂
212+--
213+--             v ::=                Values
214+--                 | ...
215+--                 | inl τ₂ v₁         tagged value (left)
216+--                 | inr τ₁ v₂         tagged value (right)
217+--
218+--             τ ::=                Types
219+--                 | ...
220+--                 | τ₁ + τ₂           sum type
221+--
222+--  Reduction:
223+--
224+--                                     t₁ ⟶ t₁'
225+--                              ------------------------                       (inl)
226+--                              inl τ₂ t₁ ⟶ inl τ₂ t₁'
227+--
228+--                                     t₂ ⟶ t₂'
229+--                              ------------------------                       (inr)
230+--                              inr τ₁ t₂ ⟶ inr τ₁ t₂'
231+--
232+--                                     t ⟶ t'
233+--                     -------------------------------------------            (case)
234+--                      case t of inl x₁ => t₁ | inr x₂ => t₂ ⟶
235+--                     case t' of inl x₁ => t₁ | inr x₂ => t₂
236+--
237+--                  -----------------------------------------------        (caseInl)
238+--                  case (inl τ₂ v₁) of inl x₁ => t₁ | inr x₂ => t₂
239+--                                 ⟶  [x₁ := v₁]t₁
240+--
241+--                  -----------------------------------------------        (caseInr)
242+--                  case (inr τ₁ v₂) of inl x₁ => t₁ | inr x₂ => t₂
243+--                                 ⟶  [x₂ := v₂]t₂
244+--
245+--  Typing:
246+--
247+--                                  Γ ⊢ t₁ ⦂ τ₁
248+--                         ----------------------------                      (inl)
249+--                             Γ ⊢ inl τ₂ t₁ ⦂ τ₁ + τ₂
250+--
251+--
252+--                                Γ ⊢ t₂ ⦂ τ₂
253+--                         ---------------------------                       (inr)
254+--                           Γ ⊢ inr τ₁ t₂ ⦂ τ₁ + τ₂
255+--
256+--
257+--                              Γ ⊢ t ⦂ τ₁ + τ₂
258+--                           x₁ ↦ τ₁; Γ ⊢ t₁ ⦂ τ₃
259+--                           x₂ ↦ τ₂; Γ ⊢ t₂ ⦂ τ₃
260+--               ----------------------------------------------------        (case)
261+--                   Γ ⊢ case t of inl x₁ => t₁ | inr x₂ => t₂ ⦂ τ₃
262+--
263+--  We use the type annotations on `inl` and `inr` to make
264+--  the typing relation deterministic (each term has at most
265+--  one type), as we did for functions.
266+

332+
333+--  Syntax:
334+--
335+--             t ::=                Terms
336+--                 | ...
337+--                 | nil τ             ∅ list
338+--                 | t₁ :: t₂          cons
339+--                 | case t₁ of        case analysis
340+--                     nil      => t₂
341+--                     | xh::xt => t₃
342+--
343+--             v ::=                Values
344+--                 | ...
345+--                 | nil τ             nil value
346+--                 | v₁ :: v₂          cons value
347+--
348+--             τ ::=                Types
349+--                 | ...
350+--                 | List τ            list of τs
351+--
352+--  Reduction:
353+--
354+--                                      t₁ ⟶ t₁'
355+--                             --------------------------                    (cons₁)
356+--                               t₁ :: t₂ ⟶ t₁' :: t₂
357+--
358+--                                      t₂ ⟶ t₂'
359+--                             --------------------------                    (cons₂)
360+--                               v₁ :: t₂ ⟶ v₁ :: t₂'
361+--
362+--                                    t₁ ⟶ t₁'
363+--                      -------------------------------------------         (listCase₁)
364+--                       (case t₁ of nil => t₂ | xh :: xt => t₃) ⟶
365+--                      (case t₁' of nil => t₂ | xh :: xt => t₃)
366+--
367+--                     ------------------------------------------          (listCaseNil)
368+--                     (case nil τ₁ of nil => t₂ | xh :: xt => t₃)
369+--                                      ⟶ t₂
370+--
371+--                    -------------------------------------------         (listCaseCons)
372+--                    (case (vh :: vt) of nil => t₂ | xh :: xt => t₃)
373+--                                ⟶ [xh:=vh][xt:=vt] t₃
374+--
375+--  Typing:
376+--
377+--                              ----------------------------                    (nil)
378+--                              Γ ⊢ nil τ₁ ⦂ List τ₁
379+--
380+--                           Γ ⊢ t₁ ⦂ τ₁      Γ ⊢ t₂ ⦂ List τ₁
381+--                  -------------------------------------------------           (cons)
382+--                               Γ ⊢ t₁ :: t₂ ⦂ List τ₁
383+--
384+--                              Γ ⊢ t₁ ⦂ List τ₁
385+--                              Γ ⊢ t₂ ⦂ τ₂
386+--                        (xh ↦ τ₁; xt ↦ List τ₁; Γ) ⊢ t₃ ⦂ τ₂
387+--                ----------------------------------------------------         (listCase)
388+--                   Γ ⊢ (case t₁ of nil => t₂ | xh :: xt => t₃) ⦂ τ₂

390+--  ### General Recursion
391+
392+--  Another facility found in most programming languages
393+--  (including Lean) is the ability to define recursive
394+--  functions. For example, we would like to be able to
395+--  define and use the factorial function like this:
396+--
397+--            let fact = λx:Nat.
398+--                         if x=0 then 1 else x * (fact (pred x))) in
399+--            fact 3.
400+--
401+--  Note that the right-hand side of this binder mentions
402+--  `fact`, the variable being bound - something that is not
403+--  allowed according to the way we defined `let` above.
404+
405+--  Extending our formalization of `let`s to handle
406+--  "recursive definitions" would require non-trivial
407+--  effort.
408+
409+--  Here is another way of presenting recursive functions
410+--  that is a bit more verbose but equally powerful and much
411+--  more straightforward to formalize: instead of writing
412+--  recursive definitions, we will define a *fixed-point
413+--  operator* called `fix` that performs the "unfolding" of
414+--  the recursive definition in the right-hand side as
415+--  needed, during reduction.
416+--
417+--  For example, instead of
418+--
419+--            fact = λax:Nat.
420+--                      if x=0 then 1 else x * (fact (pred x)))
421+--
422+--  we will write:
423+
424+--  fact =
425+--            fix
426+--              (λaf:Nat → Nat.
427+--                 λx:Nat.
428+--                    if x=0 then 1 else x * (f (pred x)))
429+
430+--  Syntax:
431+--
432+--             t ::=                Terms
433+--                 | ...
434+--                 | fix t₁            fixed-point operator
435+--
436+--  Reduction:
437+--
438+--                                      t₁ ⟶ t₁'
439+--                                  ------------------                   (fix₁)
440+--                                  fix t₁ ⟶ fix t₁'
441+--
442+--                     --------------------------------------------      (fixAbs)
443+--                     fix (λxf:τ₁.t₁) ⟶ [xf:=fix (λxf:τ₁.t₁)] t₁
444+--
445+--  Typing:
446+--
447+--                                 Γ ⊢ t₁ ⦂ τ₁ → τ₁
448+--                                 ------------------                    (fix)
449+--                                 Γ ⊢ fix t₁ ⦂ τ₁
450+
451+--  Let's see how `fixAbs` works by reducing
452+--  `fact 3 = fix F 3`, where
453+--
454+--          F = (λf. λx. if x=0 then 1 else x * (f (pred x)))
455+--
456+--  (type annotations are omitted for brevity).
457+--
458+--          fix F 3
459+--
460+--      ⟶ fixAbs + app₁
461+--
462+--          (λx. if x=0 then 1 else x * (fix F (pred x))) 3
463+--
464+--      ⟶ appAbs
465+--
466+--          if 3=0 then 1 else 3 * (fix F (pred 3))
467+--

471+--
472+--      ⟶ fixAbs + mult₂ + app₁
473+--

475+--
476+--      ⟶ predNat + mult₂ + app₂
477+--
478+--          3 * ((λx. if x=0 then 1 else x * (fix F (pred x))) 2)
479+--

481+--

576+--  ## Records
577+
578+--  As a final example, records can be presented as a
579+--  generalization of pairs:
580+--
581+--  - they are n-ary (rather than binary);
582+--  - they are accessed by *label* (rather than position).
583+
584+--  Syntax:
585+--
586+--             t ::=                          Terms
587+--                 | ...
588+--                 | {i₁=t₁, ..., in=tn}        record
589+--                 | t.i                        projection
590+--
591+--             v ::=                          Values
592+--                 | ...
593+--                 | {i₁=v₁, ..., in=vn}         record value
594+--
595+--             τ ::=                          Types
596+--                 | ...
597+--                 | {i₁:τ₁, ..., in:τn}         record type
598+
599+--  Note that this is a quite informal definition compared
600+--  to previous ones:
601+--
602+--  - it uses "`...`" in the syntax for records
603+--
604+--  - it omits a usual side condition that the labels of a
605+--    record should not contain repetitions.
606+
607+--  Reduction:
608+--
609+--                                    ti ⟶ ti'
610+--                       ------------------------------------                  (rcd)
611+--                           {i₁=v₁, ..., im=vm, in=ti , ...}
612+--                       ⟶ {i₁=v₁, ..., im=vm, in=ti', ...}
613+--
614+--                                    t ⟶ t'
615+--                                  --------------                           (proj₁)
616+--                                  t.i ⟶ t'.i
617+--
618+--                            -------------------------                    (projRcd)
619+--                            {..., i=vi, ...}.i ⟶ vi
620+
621+--  - In the first rule, `ti` must be the leftmost field
622+--    that is not a value;
623+--
624+--  - In the last rule, there should be only one field
625+--    called `i`, and all the other fields must contain
626+--    values.
627+
628+--  The typing rules are also simple:
629+--
630+--                     Γ ⊢ t₁ ⦂ τ₁     ...     Γ ⊢ tn ⦂ Tn
631+--                -----------------------------------------------------        (rcd)
632+--                Γ ⊢ {i₁=t₁, ..., in=tn} ⦂ {i₁:τ₁, ..., in:Tn}
633+--
634+--
635+--                            Γ ⊢ t ⦂ {..., i:Ti, ...}
636+--                          ---------------------------------                  (proj)
637+--                                Γ ⊢ t.i ⦂ Ti
638+
639+--  Formalizing all this would take some work.

991+  -- In pure STLC, function abstractions are values:
992+  | abs (x : String) (τ₂ : Ty) (t₁ : Tm) : IsValue <{λ ~x : ~τ₂ . ~t₁}>

1011+  | pair (v₁ v₂ : Tm) :
