288+--  The `simp` tactic is Lean's *simplifier*. It is one of the most
289+--  powerful tools in the language, and it is used heavily in real Lean
290+--  developments.
291+--
292+--  The tactic simplifies the target (the goal and/or one or more
293+--  hypotheses) by repeatedly rewriting it using a set of lemmas. At each
294+--  step it tries every lemmas in its available set the way `first` would,
295+--  applies whichever one matches via `rw`, and `repeat`s until no lemma
296+--  applies anywhere. Like `repeat`, it fails outright if it never manages
297+--  to apply a rewrite ("simp made no progress"), rather than succeeding as
298+--  a no-op the way `try` `simp` would.
299+--
300+--  `simp`'s available set of lemmas begins with a default set and can be
301+--  extended to include theorems labeled `@[simp]`. Indeed, the
302+--  characterizing lemmas we've been writing for our definitions all
303+--  throughout this book are examples of these *simplification lemmas*, or
304+--  *`simp` lemmas* as they're called by Lean programmers, only we have
305+--  refrained from annotating them as such (until now!).
