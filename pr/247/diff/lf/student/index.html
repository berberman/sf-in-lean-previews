359+namespace Algebra

361+-- This facility is very powerful, and is used extensively in Lean to define
362+-- mathematical structures that carry both operators and laws about how those
363+-- operators interact. As a simple example, let's use a typeclass to define a
364+-- *monoid*, a simple algebraic structure that includes four things:
365+
366+-- - an underlying set of data, represented by a type `α`,
367+
368+-- - an operator (which we'll write `⊗`, typed otimes) that combines two
369+--   elements of type `α` into one,
370+
371+-- - a particular element `id` of type `α`, which we call the "identity
372+--   element", and
373+
374+-- - some laws about the interaction of `·` and `id`, namely that:
375+
376+--   - `∀ x, id ⊗ x = x = x · id`, and
377+--   - `∀ x y z, x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z` (i.e., that `⊗` is associative)
378+
379+-- We can express these requirements in the form of a typeclass:
380+
381+-- first we define a notation typeclass for our operator ·
382+class OpSet (α : Type) where
383+  op : α → α → α
384+
385+infixr:70 " ⊗ " => OpSet.op
386+
387+class Monoid (α : Type) extends (OpSet α) where
388+  id : α
389+  left_identity : ∀ (x : α), id ⊗ x = x
390+  right_identity : ∀ (x : α), x ⊗ id = x
391+  associativity : ∀ (x y z : α), x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z
392+
393+-- The `extends` keyword indicates that the `Monoid` typeclass extends the
394+-- `OpSet` typeclass, which just defines a set with an operator and some
395+-- notation for it. The `Monoid` typeclass "inherits" the fields of `OpSet`,
396+-- similar to how a class would in an object-oriented language.
397+

401+-- classes.
