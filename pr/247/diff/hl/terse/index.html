411+-- This facility is very powerful, and is used extensively in
412+-- Lean to define mathematical structures that carry both
413+-- operators and laws about how those operators interact. As a
414+-- simple example, let's use a typeclass to define a *monoid*,
415+-- a simple algebraic structure that includes four things:
416+
417+-- - an underlying set of data, represented by a type `α`,
418+
419+-- - an operator (which we'll write `⊗`, typed otimes) that
420+--   combines two elements of type `α` into one,
421+
422+-- - a particular element `id` of type `α`, which we call the
423+--   "identity element", and
424+
425+-- - some laws about the interaction of `·` and `id`, namely
426+--   that:
427+
428+--   - `∀ x, id ⊗ x = x = x · id`, and
429+
430+--   - `∀ x y z, x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z` (i.e., that `⊗` is
431+--     associative)
432+
433+-- We can express these requirements in the form of a
434+-- typeclass:
435+
436+-- first we define a notation typeclass for our operator ·
437+class OpSet (α : Type) where
438+  op : α → α → α
439+
440+infixr:70 " ⊗ " => OpSet.op
441+
442+class Monoid (α : Type) extends (OpSet α) where
443+  id : α
444+  left_identity : ∀ (x : α), id ⊗ x = x
445+  right_identity : ∀ (x : α), x ⊗ id = x
446+  associativity : ∀ (x y z : α), x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z
447+
448+-- The `extends` keyword indicates that the `Monoid` typeclass
449+-- extends the `OpSet` typeclass, which just defines a set with
450+-- an operator and some notation for it. The `Monoid` typeclass
451+-- "inherits" the fields of `OpSet`, similar to how a class
452+-- would in an object-oriented language.
453+

455+-- monoid, where `0` is the identity element. Note that we
456+-- don't have to define `Nat`'s `OpSet` instance separately, we
457+-- can define a single instance that implements both classes.
458+
