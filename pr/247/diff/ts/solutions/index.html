385+namespace Algebra
386+
387+-- This facility is very powerful, and is used extensively in Lean to define
388+-- mathematical structures that carry both operators and laws about how those
389+-- operators interact. As a simple example, let's use a typeclass to define a
390+-- *monoid*, a simple algebraic structure that includes four things:
391+
392+-- - an underlying set of data, represented by a type `α`,
393+
394+-- - an operator (which we'll write `⊗`, typed otimes) that combines two
395+--   elements of type `α` into one,
396+
397+-- - a particular element `id` of type `α`, which we call the "identity
398+--   element", and
399+
400+-- - some laws about the interaction of `·` and `id`, namely that:
401+
402+--   - `∀ x, id ⊗ x = x = x · id`, and
403+--   - `∀ x y z, x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z` (i.e., that `⊗` is associative)
404+
405+-- We can express these requirements in the form of a typeclass:
406+
407+-- first we define a notation typeclass for our operator ·
408+class OpSet (α : Type) where
409+  op : α → α → α
410+
411+infixr:70 " ⊗ " => OpSet.op
412+
413+class Monoid (α : Type) extends (OpSet α) where
414+  id : α
415+  left_identity : ∀ (x : α), id ⊗ x = x
416+  right_identity : ∀ (x : α), x ⊗ id = x
417+  associativity : ∀ (x y z : α), x ⊗ (y ⊗ z) = (x ⊗ y) ⊗ z
418+
419+-- The `extends` keyword indicates that the `Monoid` typeclass extends the
420+-- `OpSet` typeclass, which just defines a set with an operator and some
421+-- notation for it. The `Monoid` typeclass "inherits" the fields of `OpSet`,
422+-- similar to how a class would in an object-oriented language.
423+
424+-- As one might expect, the `+` operator over `Nat`s forms a monoid, where `0`
425+-- is the identity element. Note that we don't have to define `Nat`'s `OpSet`
426+-- instance separately, we can define a single instance that implements both
427+-- classes.
428+
429+instance : Monoid Nat where
430+  op := Nat.add
431+  id := 0
432+  left_identity := by lia
433+  right_identity := by lia
434+  associativity := by lia

462+-- properties about monoids in general, just based on the laws defined on the

464+-- a monoid is unique. That is, if we have two monoids over the same set with
465+-- the same operator, their identity elements must also be the same:

474+-- A *group* is a special kind of monoid with an *inverse* operation `inv`,
475+-- which has the property that `∀ x, inv x ⊗ x = id = x ⊗ inv x`. We can
476+-- extend the definition of a `Monoid` to capture this new feature:
477+
478+class Group (α : Type) extends (Monoid α) where
479+  inv : α → α
480+  left_inverse : ∀ (x : α), inv x ⊗ x = id
481+  right_inverse: ∀ (x : α), x ⊗ inv x = id
