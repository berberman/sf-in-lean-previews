13--- ## Behavioral Equivaleence
14-
15--- In an earlier chapter, we investigated the correctness of a very simple
16--- program transformation: the `optimize0plus` function. The programming
17--- language we were considering was the first version of the language of
18--- arithmetic expressions -- with no variables -- so in that setting it was
19--- very easy to define what it means for a program transformation to be
20--- correct: it should always yield a program that evaluates to the same number
21--- as the original.
22-
23--- To talk about the correctness of program transformations for the full Imp
24--- language -- in particular, assignment -- we need to consider the role of
25--- mutable state and develop a more sophisticated notion of correctness, which
26--- we'll call *behavioral equivalence*.
27-
28--- For example:
29-
30--- - `X + 2` is behaviorally equivalent to `1 + X + 1`
31--- - `X - X` is behaviorally equivalent to `0`
32--- - `(X - 1) + 1` is *not* behaviorally equivalent to `X`
33-

71--- For commands, the situation is a little more subtle. We can't simply say
72--- "two commands are behaviorally equivalent if they evaluate to the same
73--- ending state whenever they are started in the same initial state," because
74--- some commands, when run in some starting states, don't terminate in any
75--- final state at all!
76-
77--- What we need instead is this: two commands are behaviorally equivalent if,
78--- for any given starting state, they either (1) both diverge or else (2) both
79--- terminate in the same final state. A compact way to express this is "if the
80--- first one terminates in a particular state then so does the second, and
81--- vice versa."
82-

84-    ∀ {st st' : State},
85-      (st =[ c₁ ]=> st') ↔ (st =[ c₂ ]=> st')

419--- Less obviously, behavioral equivalence is also a *congruence*. That is, the
420--- equivalence of two subprograms implies the equivalence of the larger
421--- programs in which they are embedded:
422-

424-
425--- cequiv c1 c1' cequiv c2 c2' -------------------------- cequiv (c1;c2)

431--- inductive definition, but simply to write down some valid implications in a
