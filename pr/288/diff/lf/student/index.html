517+-- ### Aside: Using Code Actions to Generate Match Skeletons
518+
519+-- Lean's language server can suggest *code actions*, which are small editor
520+-- commands that modify the source code. In VS Code, a lightbulb icon appears
521+-- on the left when a code action is available at your cursor. You can click
522+-- the icon or open the code action menu with `Ctrl + .` on Windows/Linux or
523+-- `Command + .` on macOS. For more information, see the [Lean 4 VSCode
524+-- extension
525+-- manual](https://github.com/leanprover/vscode-lean4/blob/master/vscode-lean4/manual/manual.md#code-actions).
526+
527+-- Some code actions can generate the explicit branches needed for pattern
528+-- matching. This is especially useful when working with `match` expressions,
529+-- or with tactics such as `cases` and `induction`, which we saw in previous
530+-- chapters.
531+
532+-- Let's look at an example using `induction`. For example, suppose we start
533+-- with the following incomplete proof:
534+
535+sf_expect_failure
536+  example (n : Nat) : Nat.beq n n := by
537+    induction n
538+
539+-- Put your cursor on `induction n` and open the code action menu. You should
540+-- see "Generate an explicit pattern match for 'induction'." in the list. If
541+-- you choose this action, Lean adds an explicit branch for each constructor:
542+
543+example (n : Nat) : Nat.beq n n := by
544+  induction n with
545+  | zero => sorry
546+  | succ n _ => sorry
547+
548+-- This gives us basic structure of the proof without requiring us to write
549+-- each branch by hand. We can then focus on proving each case.
550+
551+-- One possible proof is:
552+
553+example (n : Nat) : Nat.beq n n := by
554+  induction n with
555+  | zero => exact (beq_self zero)
556+  | succ n ih => rw [Nat.beq, ih]
557+
558+-- Note that Lean used `_` for the induction hypothesis in the generated
559+-- `succ` branch. At that point, Lean didn't know whether the unfinished proof
560+-- would need to refer to the hypothesis. Since we use it in `rw`, we replace
561+-- `_` with the name `ih`.
562+
563+-- In later chapters, we will see some tactics that can make such inaccessible
564+-- names available again.
565+
566+-- The same trick also works for `match` expressions. For example, suppose we
567+-- start with
568+

571+    match n

573+-- Lean can generate the missing branches:
574+

577+    match n with
578+    | 0 => _
579+    | n + 1 => _

581+-- You can use code actions freely to fill out `induction`, `case`, and
582+-- `match` branches in this book.

234243 -- The `dsimp` tactic ("definitionally simplify") unfolds definitions and
235244 -- performs definitional simplifications. You can give it hints in square
276285 
277286 example (n m : Nat) (h : 2 * n = m * 2) : n + n = m + m := by
278287   rw [Nat.mul_comm, Nat.mul_two, Nat.mul_two] at h
288+  exact h
289+
290+-- But `rw` rewrites only one instance of a *definition* at a time. When a
291+-- hypothesis mentions the same function at several different arguments, each
292+-- one needs its own rewrite.
293+
294+example (n m k : Nat) (h : square n + square m + square k = 0) :
295+    n * n + m * m + k * k = 0 := by
296+  rw [square, square, square] at h
297+  exact h
298+
299+-- `dsimp` unfolds *every* instance at once, so one hint suffices no matter
300+-- how many times the definition appears.
301+
302+example (n m k : Nat) (h : square n + square m + square k = 0) :
303+    n * n + m * m + k * k = 0 := by
304+  dsimp [square] at h
