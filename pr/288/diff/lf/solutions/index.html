611+
612+-- Lean's language server can suggest *code actions*, which are small editor
613+-- commands that modify the source code. In VS Code, a lightbulb icon appears
614+-- on the left when a code action is available at your cursor. You can click
615+-- the icon or open the code action menu with `Ctrl + .` on Windows/Linux or
616+-- `Command + .` on macOS. For more information, see the [Lean 4 VSCode
617+-- extension
618+-- manual](https://github.com/leanprover/vscode-lean4/blob/master/vscode-lean4/manual/manual.md#code-actions).
619+
620+-- Some code actions can generate the explicit branches needed for pattern
621+-- matching. This is especially useful when working with `match` expressions,
622+-- or with tactics such as `cases` and `induction`, which we saw in previous
623+-- chapters.
624+
625+-- Let's look at an example using `induction`. For example, suppose we start
626+-- with the following incomplete proof:
627+
628+sf_expect_failure
629+  example (n : Nat) : Nat.beq n n := by
630+    induction n
631+
632+-- Put your cursor on `induction n` and open the code action menu. You should
633+-- see "Generate an explicit pattern match for 'induction'." in the list. If
634+-- you choose this action, Lean adds an explicit branch for each constructor:
635+
636+example (n : Nat) : Nat.beq n n := by
637+  induction n with
638+  | zero => sorry
639+  | succ n _ => sorry
640+
641+-- This gives us basic structure of the proof without requiring us to write
642+-- each branch by hand. We can then focus on proving each case.
643+
644+-- One possible proof is:
645+
646+example (n : Nat) : Nat.beq n n := by
647+  induction n with
648+  | zero => exact (beq_self zero)
649+  | succ n ih => rw [Nat.beq, ih]
650+
651+-- Note that Lean used `_` for the induction hypothesis in the generated
652+-- `succ` branch. At that point, Lean didn't know whether the unfinished proof
653+-- would need to refer to the hypothesis. Since we use it in `rw`, we replace
654+-- `_` with the name `ih`.
655+
656+-- In later chapters, we will see some tactics that can make such inaccessible
657+-- names available again.
658+
659+-- The same trick also works for `match` expressions. For example, suppose we
660+-- start with
661+
662+sf_expect_failure
663+  def isZero (n : Nat) : Bool :=
664+    match n
665+
666+-- Lean can generate the missing branches:
667+
668+sf_expect_failure
669+  def isZero (n : Nat) : Bool :=
670+    match n with
671+    | 0 => _
672+    | n + 1 => _

675+-- `match` branches in this book.
