674665 --  ### Desugaring Notations
675666 
676---  The `imp { … }` notation, together with the delaborators, is purely a
677---  convenience for reading and writing programs. Occasionally, such as
678---  when debugging a definition or a stuck proof, the concrete syntax
679---  `hide`s the underlying structure we want to see. For those moments we
680---  can switch the Imp notation off in Lean's output with
681---  `set_option pp.notation false`, which our delaborators honor.
682-
683---  Note that unlike a `def`, `imp { … }` is a `macro` which is expanded
684---  during elaboration, **before** the resulting term is type-checked. So
685---  `fact_in_lean` is not a program hidden behind a layer of notation that
686---  a proof must first peel back; it simply **is** the underlying tree of
687---  `Com`, `Aexp`, and `Bexp` constructors. Consequently, when a proof goal
688---  mentions an Imp program, tactics such as `cases`, `injection`, and
689---  `simp` already act on those constructors directly -- there is nothing
690---  to "unfold". The delaborators affect only how that tree is
691---  **displayed**. Nevertheless, seeing the raw constructors is sometimes
692---  very helpful!
