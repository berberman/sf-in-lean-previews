670662 --  ### Desugaring Notations
671663 
672---  The `imp { … }` notation, together with the delaborators, is purely a
673---  convenience for reading and writing programs. Occasionally, such as
674---  when debugging a definition or a stuck proof, the concrete syntax
675---  `hide`s the underlying structure we want to see. For those moments we
676---  can switch the Imp notation off in Lean's output with
677---  `set_option pp.notation false`, which our delaborators honor.
678---
679---  Note that unlike a `def`, `imp { … }` is a `macro` which is expanded
680---  during elaboration, **before** the resulting term is type-checked. So
681---  `fact_in_lean` is not a program hidden behind a layer of notation that
682---  a proof must first peel back; it simply **is** the underlying tree of
683---  `Com`, `Aexp`, and `Bexp` constructors. Consequently, when a proof goal
684---  mentions an Imp program, tactics such as `cases`, `injection`, and
685---  `simp` already act on those constructors directly -- there is nothing
686---  to "unfold". The delaborators affect only how that tree is
687---  **displayed**. Nevertheless, seeing the raw constructors is sometimes
688---  very helpful!
