618609 --  ### Desugaring Notations
619610 
620---  The `imp { … }` notation, together with the delaborators, is purely a
621---  convenience for reading and writing programs. Occasionally, such as
622---  when debugging a definition or a stuck proof, the concrete syntax
623---  `hide`s the underlying structure we want to see. For those moments we
624---  can switch the Imp notation off in Lean's output with
625---  `set_option pp.notation false`, which our delaborators honor.
626-
627---  Note that unlike a `def`, `imp { … }` is a `macro` which is expanded
628---  during elaboration, **before** the resulting term is type-checked. So
629---  `fact_in_lean` is not a program hidden behind a layer of notation that
630---  a proof must first peel back; it simply **is** the underlying tree of
631---  `Com`, `Aexp`, and `Bexp` constructors. Consequently, when a proof goal
632---  mentions an Imp program, tactics such as `cases`, `injection`, and
633---  `simp` already act on those constructors directly -- there is nothing
634---  to "unfold". The delaborators affect only how that tree is
635---  **displayed**. Nevertheless, seeing the raw constructors is sometimes
636---  very helpful!
