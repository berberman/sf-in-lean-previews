1310+--  The Logic chapter's "Working with Decidable Properties"

1316+--
1317+--  Recall from "Why We Need Typeclasses" that
1318+--  `[0, 1].elemPoly 0`'s `==` is filled in automatically by
1319+--  Lean, in contrast to `[0, 1].elemPolyEq Nat.beq 0`,
1320+--  which is handed `Nat.beq` explicitly. It's tempting to
1321+--  assume Lean fills in that very function as the `BEq`

1330+--  Not `Nat.beq` at all! Recall that `BEq`'s only field is
1331+--  `beq : α → α → Bool` — nothing more.
1332+--  `instBEqOfDecidableEq` builds a `BEq α` instance from a
1333+--  `DecidableEq α` one by setting
1334+--  `beq a b := decide (a = b)`: it takes the proof-carrying
1335+--  `Decidable (a = b)` value and uses `decide` to strip
