1411---  The crucial difference between the two worlds is decidability. Every
1412---  (closed) Lean expression of type `Bool` can be simplified in a finite
1413---  number of steps to either `true` or `false` — i.e., there is a
1414---  terminating mechanical procedure for deciding whether or not it is
1415---  true.
1416---
1417---  This means that, for example, the type `Nat → Bool` is inhabited only
1418---  by functions that, given a `Nat`, always yield either `true` or `false`
1419---  in finite time; and this, in turn, means (by a standard computability
1420---  argument) that there is no function in `Nat → Bool` that checks whether
1421---  a given number is the code of a terminating Turing machine.
1422---
1423---  By contrast, the type `Prop` includes both decidable and undecidable
1424---  mathematical propositions; in particular, the type `Nat → Prop` does
1425---  contain functions representing properties like "the nth Turing machine
1426---  halts." The second row in the table follows directly from this
1427---  essential difference. To evaluate a pattern match (or conditional) on a
1428---  boolean, we need to know whether the scrutinee evaluates to `true` or
1429---  `false`; this only works for `Bool`, not `Prop`.
1430---

1435---  properties, we have two options when we want to formalize a property
