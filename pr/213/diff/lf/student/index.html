1787+-- In this exercise, we will model part of a database storing information
1788+-- about travelers passing through an airport. The database contains one entry
1789+-- per traveler, recording information about where the traveler is in the
1790+-- airport process and the contents of their current carry-on bag.
1791+
1792+-- We will implement several operations on these entries, state intended
1793+-- properties of the database's behavior, and prove that the implementation
1794+-- satisfies them.
1795+
1796+namespace Airport
1797+
1798+-- For simplicity, a carry-on bag either contains a prohibited item, such as a
1799+-- liquid that exceeds the allowed limit, causing it to fail inspection, or
1800+-- contains only ordinary items.
1801+
1802+inductive BagContent : Type where
1803+  | prohibited
1804+  | ordinary

1806+-- After a traveler checks in, the database also records the result of the
1807+-- most recent security screening of their carry-on bag.
1808+
1809+inductive ScreeningStatus : Type where
1810+  | notScreened
1811+  | cleared
1812+  | blocked

1814+-- Next, we define the possible stages of the airport process a traveler can
1815+-- inhabit:
1816+

1818+
1819+-- - they have a ticket but have not yet checked in;
1820+
