25+--  ## The `apply` Tactic
26+
27+--  We often encounter situations where the goal to be proved is *exactly*
28+--  the same as some hypothesis in the context or some previously proved
29+--  lemma.
30+
31+--  The `apply` tactic is useful when the goal is instead the conclusion of
32+--  an implication.
33+
34+--  For example, suppose we have a hypothesis `h : p → q` and our goal is
35+--  `q`. We can use `apply h` to replace the goal `q` with the premise `p`:
36+
37+example (p q : Prop) (h : p → q) (hp : p) : q := by
38+  apply h
39+  exact hp
40+
41+--  The `apply` tactic also works with hypotheses and lemmas whose types
42+--  are implications. If the conclusion of the implication matches the
43+--  current goal, its premises become new subgoals to be proved.
44+
45+example (n m o p : Nat) (hnm : n = m) (h : n = m → [n, o] = [m, p]) :
46+    [n, o] = [m, p] := by
47+  apply h
48+  exact hnm
49+
50+--  When we use `apply h`, Lean tries to match the conclusion of the type
51+--  of `h` with the current goal. Here `h : n = m → [n, o] = [m, p]` has
52+--  conclusion `[n, o] = [m, p]`, which matches the current goal. Lean then
53+--  replaces the goal with the premise that is still needed, `n = m`. Then
54+--  we close the goal with `exact hnm`.
55+--
56+--  More generally, the type of a theorem or hypothesis used with `apply`
57+--  may have universally quantified variables and premises. Lean tries to
58+--  match its conclusion with the current goal to determine appropriate
59+--  values for the quantified variables.
60+
61+example (n m : Nat) (h₁ : (n, n) = (m, m))
62+    (h₂ : ∀ (q r : Nat), (q, q) = (r, r) → [q] = [r]) :
63+    [n] = [m] := by
64+  apply h₂
65+  exact h₁

1016+--  ## Using `cases` on Expressions
1017+
1018+--  We have seen many examples where `cases` is used to perform case
1019+--  analysis of the value of some variable. Sometimes we need to reason by
1020+--  cases on the result of some *expression*. We can also do this with
1021+--  `cases`.
1022+--
1023+--  Here is an example:
1024+
1025+def chooseIf {α : Type} (test : α → Bool) (x y : α) : α :=
1026+  if test x then x else y
1027+
1028+theorem chooseIf_self {α : Type} (test : α → Bool) (x : α) :
1029+    chooseIf test x x = x := by
1030+  rw [chooseIf]
1031+  cases test x <;> rfl
1032+
1033+--  After *unfolding* `chooseIf` in the above proof, we find that we are
1034+--  stuck on `(if test x = true then x else x) = x`. But either `test x` is
1035+--  `true` or it isn't, so we can use `cases (test x)` to let us reason
1036+--  about the two cases.
1037+--
1038+--  In general, the `cases` tactic can perform case analysis on the results
1039+--  of arbitrary computations. If `e` has an inductively defined type `T`,
1040+--  then `cases e` generates one subgoal for each constructor of `T`,
1041+--  specializing the goal to that case. It does not necessarily rewrite
1042+--  occurrences of `e` in hypotheses; when that information is needed, we
1043+--  can save an equation as described below.
