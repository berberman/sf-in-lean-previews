10---  ## Recommended Citation Format
7+--  This is Hoare Logic, volume 2 of *Software Foundations
8+--  in Lean*. It develops formal techniques for reasoning
9+--  about what programs do. For example, with techniques we
10+--  present, one can prove that an algorithm sorts an array
11+--  or that a compiler optimization does not incorrectly
12+--  change the behavior of the program it optimizes. This
13+--  volume complements Type Systems, which develops
14+--  techniques for establishing properties of *all* programs
15+--  written in a given language; the two volumes can be read
16+--  in either order, and both build on the material in
17+--  Logical Foundations.
18+
19+--  ## Overview
20+
21+--  To reason about a program, we first need a way of
22+--  representing it as a mathematical object, so that we can
23+--  talk about it precisely, together with a way of
24+--  describing its behavior in terms of a mathematical
25+--  function or relation. Our main tool for this is
26+--  *operational semantics*, a method of specifying the
27+--  meaning of a programming language by writing an abstract
28+--  interpreter for it.
29+--
30+--  The programming language we consider throughout this
31+--  volume is *Imp*, a toy language capturing the core
32+--  features of conventional imperative programming:
33+--  variables, assignment, conditionals, and loops. Imp's
34+--  arithmetic and boolean expressions are developed as
35+--  their own simple sublangage, called Slang.
36+--
37+--  We study two different ways of reasoning about the
38+--  behavior of Imp programs.
39+--
40+--  First, we consider what it means to say that two Imp
41+--  programs are *equivalent*, in the sense that they
42+--  produce the same behavior when started in any initial
43+--  state. This notion of equivalence becomes a criterion
44+--  for judging the correctness of program transformations,
45+--  such as those used in compilers and optimizers. We build
46+--  a simple optimizer for Imp and prove that it preserves
47+--  the behavior of the programs it transforms.
48+--
49+--  Second, we develop a methodology for proving that a
50+--  given Imp program satisfies a formal specification of
51+--  its behavior. We introduce *Hoare triples* — Imp
52+--  programs annotated with pre- and post-conditions
53+--  describing what they expect to be true of the state in
54+--  which they start and what they promise to be true of the
55+--  state in which they terminate — and the reasoning
56+--  principles of *Hoare Logic*, a domain-specific logic for
57+--  compositional reasoning about imperative programs. We
58+--  then develop *decorated programs*, a practical notation
59+--  for writing out Hoare Logic proofs alongside the code
60+--  they justify.
61+--
62+--  The techniques this volume presents are relatively
63+--  simple, but they nevertheless underpin today's
64+--  real-world software and hardware verification efforts.
65+

72+--  the same "advanced"/"optional" markings, and star
73+--  ratings.

80+--  you; download and unzip it, open the resulting directory

82+--  `HL/Slang.lean`) to get started.
83+--
84+--  If you are reading on your own, clone the
