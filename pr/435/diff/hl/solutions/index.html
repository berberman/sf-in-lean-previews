9---  ## Recommended Citation Format
7+--  This is Hoare Logic, volume 2 of *Software Foundations in Lean*. It
8+--  develops formal techniques for reasoning about what programs do. For
9+--  example, with techniques we present, one can prove that an algorithm
10+--  sorts an array or that a compiler optimization does not incorrectly
11+--  change the behavior of the program it optimizes. This volume
12+--  complements Type Systems, which develops techniques for establishing
13+--  properties of *all* programs written in a given language; the two
14+--  volumes can be read in either order, and both build on the material in
15+--  Logical Foundations.
16+
17+--  ## Overview
18+
19+--  To reason about a program, we first need a way of representing it as a
20+--  mathematical object, so that we can talk about it precisely, together
21+--  with a way of describing its behavior in terms of a mathematical
22+--  function or relation. Our main tool for this is *operational
23+--  semantics*, a method of specifying the meaning of a programming
24+--  language by writing an abstract interpreter for it.
25+--
26+--  The programming language we consider throughout this volume is *Imp*, a
27+--  toy language capturing the core features of conventional imperative
28+--  programming: variables, assignment, conditionals, and loops. Imp's
29+--  arithmetic and boolean expressions are developed as their own simple
30+--  sublangage, called Slang.
31+--
32+--  We study two different ways of reasoning about the behavior of Imp
33+--  programs.
34+--
35+--  First, we consider what it means to say that two Imp programs are
36+--  *equivalent*, in the sense that they produce the same behavior when
37+--  started in any initial state. This notion of equivalence becomes a
38+--  criterion for judging the correctness of program transformations, such
39+--  as those used in compilers and optimizers. We build a simple optimizer
40+--  for Imp and prove that it preserves the behavior of the programs it
41+--  transforms.
42+--
43+--  Second, we develop a methodology for proving that a given Imp program
44+--  satisfies a formal specification of its behavior. We introduce *Hoare
45+--  triples* — Imp programs annotated with pre- and post-conditions
46+--  describing what they expect to be true of the state in which they start
47+--  and what they promise to be true of the state in which they terminate —
48+--  and the reasoning principles of *Hoare Logic*, a domain-specific logic
49+--  for compositional reasoning about imperative programs. We then develop
50+--  *decorated programs*, a practical notation for writing out Hoare Logic
51+--  proofs alongside the code they justify.
52+--
53+--  The techniques this volume presents are relatively simple, but they
54+--  nevertheless underpin today's real-world software and hardware
55+--  verification efforts.
56+

63+--  star ratings.

72+--
