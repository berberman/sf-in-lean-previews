626+-- You might have noticed that `filter_cons_of_pos` and `filter_cons_of_neg`
627+-- have implicit parameters, such as `head` and `tail`, that do not have type
628+-- `Type` like `α` does. This is a standard Lean convention for lemmas that
629+-- are likely to be used by `rw` or `dsimp` when their values can be inferred
630+-- by unification.
631+
632+-- For example, suppose you were using this theorem to rewrite
633+-- `filter Nat.even (3 :: rest)`. Matching that expression against the
634+-- theorem's left-hand side `filter test (head :: tail)` establishes that
635+-- `test = Nat.even`, `head = 3`, `tail = rest`, and `α = Nat`. By making
636+-- these arguments implicit, Lean automatically inserts a blank `_` for each
637+-- of them when you apply the theorem — you don't have to add the `_`
638+-- yourself.
639+
640+-- Note that `h : test head` is not implicit, it's explicit. That's because it
641+-- cannot be solved by unification, i.e., Lean can't prove that
642+-- `Nat.even 3 = true` that way. It's a general proof obligation.
643+
644+-- We'll follow the Lean standard convention from now on.
