669+-- You might have noticed that `filter_cons_of_pos` and `filter_cons_of_neg`
670+-- have implicit parameters, such as `head` and `tail`, that do not have type
671+-- `Type` like `α` does. This is a standard Lean convention for lemmas that
672+-- are likely to be used by `rw` or `dsimp` when their values can be inferred
673+-- by unification.
674+
675+-- For example, suppose you were using this theorem to rewrite
676+-- `filter Nat.even (3 :: rest)`. Matching that expression against the
677+-- theorem's left-hand side `filter test (head :: tail)` establishes that
678+-- `test = Nat.even`, `head = 3`, `tail = rest`, and `α = Nat`. By making
679+-- these arguments implicit, Lean automatically inserts a blank `_` for each
680+-- of them when you apply the theorem — you don't have to add the `_`
681+-- yourself.
682+
683+-- Note that `h : test head` is not implicit, it's explicit. That's because it
684+-- cannot be solved by unification, i.e., Lean can't prove that
685+-- `Nat.even 3 = true` that way. It's a general proof obligation.
686+
