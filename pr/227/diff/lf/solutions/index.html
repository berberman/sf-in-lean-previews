19+-- ## Welcome
20+
21+-- This is the entry point to a series of electronic textbooks on various
22+-- aspects of *Software Foundations*, the mathematical underpinnings of
23+-- reliable software. Topics in the series include basic concepts of logic,
24+-- computer-assisted theorem proving, the Rocq prover, functional programming,
25+-- operational semantics, logics and techniques for reasoning about programs,
26+-- static type systems, property-based random testing, and verification of
27+-- practical C code. The exposition is intended for a broad range of readers,
28+-- from advanced undergraduates to PhD students and researchers. No specific
29+-- background in logic or programming languages is assumed, though a degree of
30+-- mathematical maturity will be helpful.
31+
32+-- The principal novelty of the series is that it is one hundred percent
33+-- formalized and machine-checked: each text is literally a script for Rocq.
34+-- The books are intended to be read alongside (or inside) an interactive
35+-- session with Rocq. All the details in the text are fully formalized in
36+-- Rocq, and most of the exercises are designed to be worked using Rocq.
37+
38+-- The files in each book are organized into a sequence of core chapters,
39+-- covering about one semester's worth of material and organized into a
40+-- coherent linear narrative, plus a number of "offshoot" chapters covering
41+-- additional topics. All the core chapters are suitable for both upper-level
42+-- undergraduate and graduate students.
43+
44+-- This book, *Logical Foundations*, lays groundwork for the others,
45+-- introducing the reader to the basic ideas of functional programming,
46+-- constructive logic, and the Rocq prover.

48+-- ## Overview
49+
50+-- Building reliable software is hard -- really hard. The scale and complexity
51+-- of modern systems, the number of people involved, and the range of demands
52+-- placed on them make it challenging to build software that is even
53+-- more-or-less correct, much less 100% correct. At the same time, the
54+-- increasing degree to which information processing is woven into every
55+-- aspect of society greatly amplifies the cost of bugs and insecurities.
56+
57+-- Computer scientists and software engineers have responded to these
58+-- challenges by developing a host of techniques for improving software
59+-- reliability, ranging from recommendations about managing software projects
60+-- teams (e.g., extreme programming) to design philosophies for libraries
61+-- (e.g., model-view-controller, publish-subscribe, etc.) and programming
62+-- languages (e.g., object-oriented programming, functional programming, ...)
63+-- to mathematical techniques for specifying and reasoning about properties of
64+-- software and tools for helping validate these properties. The *Software
65+-- Foundations* series is focused on this last set of tools.
66+
67+-- This volume weaves together three conceptual threads:
68+
69+-- (A) basic tools from *logic* for making and justifying precise claims about
70+-- programs;
71+
72+-- (B) the use of *proof assistants* (or *provers*) to construct rigorous
73+-- logical arguments;
74+
75+-- (C) *functional programming*, both as a method of programming that
76+-- simplifies reasoning about programs and as a bridge between programming and
77+-- logic.
78+
79+-- ### Logic
80+
81+-- Logic is the field of study whose subject matter is *proofs* --
82+-- unassailable arguments for the truth of particular propositions. Volumes
83+-- have been written about the central role of logic in computer science.
84+-- Manna and Waldinger called it "the calculus of computer science," while
85+-- Halpern et al.'s paper *On the Unusual Effectiveness of Logic in Computer
86+-- Science* catalogs scores of ways in which logic offers critical tools and
87+-- insights. Indeed, they observe that, "As a matter of fact, logic has turned
88+-- out to be significantly more effective in computer science than it has been
89+-- in mathematics. This is quite remarkable, especially since much of the
90+-- impetus for the development of logic during the past one hundred years came
91+-- from mathematics."
92+
93+-- In particular, the fundamental tools of *inductive proof* are ubiquitous in
94+-- all of computer science. You have surely seen them before, perhaps in a
95+-- course on discrete math or analysis of algorithms, but in this course we
96+-- will examine them more deeply than you have probably done so far.

102+-- ### Proof Assistants
103+
104+-- The flow of ideas between logic and computer science has not been
105+-- unidirectional: CS has also made important contributions to logic. One of
106+-- these has been the development of software tools for helping construct
107+-- proofs of logical propositions. These tools fall into two broad categories:
108+
109+-- - *Automated theorem provers* provide "push-button" operation: you give them
110+--   a proposition and they return either *true* or *false* (or, sometimes,
111+--   *don't know: ran out of time*). Although their reasoning capabilities are
112+--   still limited, they have matured tremendously in recent decades and are
113+--   used now in a multitude of settings. Examples of such tools include SAT
114+--   solvers, SMT solvers, and model checkers.
115+
116+-- - *Proof assistants* are hybrid tools that automate the more routine aspects
117+--   of building proofs while depending on human guidance for more difficult
118+--   aspects. Widely used proof assistants include Isabelle, Agda, Twelf, ACL2,
119+--   PVS, F*, HOL4, Lean, and Rocq, among many others.
120+
121+-- This course is based around Rocq, a proof assistant that has been under
122+-- development since 1983 and has attracted a large community of users in both
123+-- research and industry. Rocq provides a rich environment for interactive
124+-- development of machine-checked formal reasoning. The kernel of the Rocq
125+-- system is a simple proof-checker, which guarantees that only correct
126+-- deduction steps are ever performed. On top of this kernel, the Rocq
127+-- environment provides high-level facilities for proof development, including
128+-- a large library of common definitions and lemmas, powerful tactics for
129+-- constructing complex proofs semi-automatically, and a special-purpose
130+-- programming language for defining new proof-automation tactics for specific
131+-- situations.
132+
133+-- Rocq has been a critical enabler for a huge variety of work across computer
134+-- science and mathematics:
135+
136+-- - As a *platform for modeling programming languages*, it has become a
137+--   standard tool for researchers who need to describe and reason about complex
138+--   language definitions. It has been used, for example, to check the security
139+--   of the JavaCard platform, obtaining the highest level of common criteria
140+--   certification, and for formal specifications of the x86 and LLVM
141+--   instruction sets and programming languages such as C.
142+
143+-- - As an *environment for developing formally certified software and
144+--   hardware*, Rocq has been used, for example, to build CompCert, a
145+--   fully-verified optimizing compiler for C, and CertiKOS, a fully verified
146+--   hypervisor, for proving the correctness of subtle algorithms involving
147+--   floating point numbers, and as the basis for CertiCrypt, FCF, and SSProve,
148+--   which are frameworks for proving cryptographic algorithms secure. It is
149+--   also being used to build verified implementations of the open-source RISC-V
150+--   processor architecture.
151+
152+-- - As a *realistic environment for functional programming with dependent
153+--   types*, it has inspired numerous innovations. For example, Hoare Type
154+--   Theory embeds reasoning about "pre-conditions" and "post-conditions" (an
155+--   extension of the *Hoare Logic* we will see later in this course) in Rocq.
156+
157+-- - As a *proof assistant for higher-order logic*, it has been used to validate
158+--   a number of important results in mathematics. For example, its ability to
159+--   include complex computations inside proofs made it possible to develop the
160+--   first formally verified proof of the 4-color theorem. This proof had
161+--   previously been controversial among mathematicians because it required
162+--   checking a large number of configurations using a program. In the Rocq
163+--   formalization, everything is checked, including the correctness of the
164+--   computational part. More recently, an even more massive effort led to a
165+--   Rocq formalization of the Feit-Thompson Theorem, the first major step in
166+--   the classification of finite simple groups.
167+

172+-- ### Functional Programming
173+
174+-- The term *functional programming* refers both to a collection of
175+-- programming idioms that can be used in almost any programming language and
176+-- to a family of programming languages designed to emphasize these idioms,
177+-- including Haskell, OCaml, Standard ML, F##, Scala, Scheme, Racket, Common
178+-- Lisp, Clojure, Erlang, F*, and Rocq.
179+
180+-- Functional programming has been developed over many decades -- indeed, its
181+-- roots go back to Church's lambda-calculus, which was invented in the 1930s,
182+-- well *before* the first electronic computers! But since the early '90s it
183+-- has enjoyed a surge of interest among industrial engineers and language
184+-- designers, playing a key role in high-value systems at companies like Jane
185+-- Street Capital, Microsoft, Facebook, Twitter, and Ericsson.
186+
187+-- The most basic tenet of functional programming is that, as much as
188+-- possible, computation should be *pure*, in the sense that the only effect
189+-- of execution should be to produce a result: it should be free from *side
190+-- effects* such as I/O, assignments to mutable variables, redirecting
191+-- pointers, etc. For example, whereas an *imperative* sorting function might
192+-- take a list of numbers and rearrange its pointers to put the list in order,
193+-- a pure sorting function would take the original list and return a *new*
194+-- list containing the same numbers in sorted order.
195+
196+-- A significant benefit of this style of programming is that it makes
197+-- programs easier to understand and reason about. If every operation on a
198+-- data structure yields a new data structure, leaving the old one intact,
199+-- then there is no need to worry about how that structure is being shared and
200+-- whether a change by one part of the program might break an invariant relied
201+-- on by another part of the program. These considerations are particularly
202+-- critical in concurrent systems, where every piece of mutable state that is
203+-- shared between threads is a potential source of pernicious bugs. Indeed, a
204+-- large part of the recent interest in functional programming in industry is
205+-- due to its simpler behavior in the presence of concurrency.
206+
207+-- Another reason for the current excitement about functional programming is
208+-- related to the first: functional programs are often much easier to
209+-- parallelize and physically distribute than their imperative counterparts.
210+-- If running a computation has no effect other than producing a result, then
211+-- it does not matter *where* it is run. Similarly, if a data structure is
212+-- never modified destructively, then it can be copied freely, across cores or
213+-- across the network. Indeed, the "Map-Reduce" idiom, which lies at the heart
214+-- of massively distributed query processors like Hadoop and is used by Google
215+-- to index the entire web is a classic example of functional programming.
216+
217+-- For purposes of this course, functional programming has yet another
218+-- significant attraction: it serves as a bridge between logic and computer
219+-- science. Indeed, Rocq itself can be viewed as a combination of a small but
220+-- extremely expressive functional programming language plus a set of tools
221+-- for stating and proving logical assertions. Moreover, when we come to look
222+-- more closely, we find that these two sides of Rocq are actually aspects of
223+-- the very same underlying machinery -- i.e., *proofs are programs*.
224+
225+-- ### Rocq vs. Coq
226+
227+-- Until 2025, the Rocq prover was known as Coq. According to the official
228+-- webpage, "The name 'Coq' referenced the Calculus of Constructions (CoC),
229+-- the foundational system it is based on, as well as one of its creators,
230+-- Thierry Coquand. Additionally, it paid homage to the French national
231+-- symbol, the rooster. The new name, 'the Rocq Prover', honors Inria
232+-- Rocquencourt, the original site where the prover was developed. It also
233+-- alludes to the mythological bird Roc (or Rokh), symbolizing strength and
234+-- not so disconnected to a rooster. Furthermore, the name conveys a sense of
235+-- solidity, and its unintended connection to music adds a pleasant
236+-- resonance."
237+
238+-- The current release of Software Foundations is still in a transitional
239+-- state, and you will see references to both Coq and Rocq.

381+-- ### Alternative Installation Methods
382+
383+-- If you prefer, there are several other ways to use Rocq. You will need:
384+
385+-- - A current installation of Rocq, available from the Rocq home page
386+--   (<https://rocq-prover.org/install>). The "Rocq Platform" offers the easiest
387+--   installation experience for most people, especially on Windows.
388+
389+-- - An IDE for interacting with Rocq. There are several choices:
390+
391+-- - *VsCoq* is an extension for Visual Studio Code that offers a simple
392+--   interface via a familiar IDE. This option is the recommended default.
393+
394+-- VsCoq can be used as an ordinary IDE or it can be combined with Docker (see
395+-- below) for a lightweight installation experience.
396+
397+-- - *Proof General* is an Emacs-based IDE. It tends to be preferred by users
398+--   who are already comfortable with Emacs. It requires a separate installation
399+--   (google "Proof General", but generally all you need to do is
400+--   `M-x package-list-packages`, then select the `proof-general` package from
401+--   the list and hit the `i` key for install, then hit the `x` key for
402+--   execute).
403+
404+-- There are only a few commands you need to know to use ProofGeneral
405+-- effectively. They are:
406+
407+-- - `C-c C-n`: send the next command to Rocq.
408+
409+-- - `C-c C-u`: undo (retract) the most recently executed command.
410+
411+-- - `C-c C-RET`: submit everything up to the current cursor location to Rocq
412+--   for processing.
413+
414+-- - `C-c C-.`: move the cursor to the end of the last command which has been
415+--   processed by Rocq.
416+
417+-- - `C-c .`: toggle "electric terminator mode". When this mode is turned on,
418+--   simply typing a period will send the current command to Rocq (normally you
419+--   have to type a period and then type `C-c C-n`).
420+
421+-- Adventurous users of Rocq within Emacs may want to check out extensions
422+-- such as `company-coq` and `control-lock`.
423+
424+-- - *RocqIDE* is a simpler stand-alone IDE. It is distributed with the Rocq
425+--   Platform, so it should be available once you have Rocq installed. It can
426+--   also be compiled from scratch, but on some platforms this may involve
427+--   installing additional packages for GUI libraries and such.
